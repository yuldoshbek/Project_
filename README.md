Инструмент управления проектами для аппарата заместителя директора Агентства
космических исследований и технологий Республики Узбекистан («Ўзбеккосмос»).

**Пользователей двое:** личный помощник вносит данные, заместитель директора смотрит и
анализирует — на экране доклада и в Telegram. Вехи и сроки живут в его
Google-календаре, встречи оттуда видны в системе.

---

## О чём проект

Агентство одновременно ведёт десятки проектов, мини-проектов и срочных поручений: космический
мониторинг, дистанционное зондирование Земли, международное сотрудничество, инфраструктурные
и регуляторные инициативы. Сегодня это управляется вручную — через мессенджеры, отдельные
файлы и личный контроль помощника руководителя. Единой точки правды по статусам и срокам нет.

Из этого следуют пять конкретных проблем, и каждую ORBITA закрывает своим блоком:

| Проблема | Что делает система |
|---|---|
| Руководитель не видит общей картины без опроса кураторов | Дашборд со «светофором»: красная зона видна за 30 секунд |
| Срочные задачи теряются в общем потоке | Приоритет «Срочно» с таймером эскалации |
| Нет единой истории по проекту | Карточка проекта: вехи, задачи, файлы, комментарии, журнал изменений |
| Просрочки обнаруживаются постфактум | Напоминания за 1, 3, 7 дней и автоэскалация по цепочке |
| Помощник вручную собирает статусы | Экран «Сегодня»: весь периметр руководителя на одном экране |

Ключевое, чего нет в коробочных продуктах: **экран доклада, который читается за
30 секунд**, **утренняя сводка в Telegram**, **двусторонняя синхронизация с
Google-календарём** и **поиск, одинаково работающий на русском, узбекской кириллице и
узбекской латинице**.

Два свойства определяют весь остальной проект: презентационный слой — это и есть
продукт, а стоимость ручного ввода решает, выживет ли система. Разбор —
[COUNCIL-0002](docs/council/COUNCIL-0002.md).

## Кто пользуется

Две роли: **помощник** (вносит всё) и **руководитель** (смотрит, читает сводки,
принимает решения по проектам на контроле). Разграничения доступа между ними нет —
делить нечего ([ADR-0011](docs/adr/ADR-0011-two-user-scope.md)).

Кураторы проектов и исполнители задач — **сотрудники агентства, а не пользователи**:
они живут в справочнике, чтобы было понятно, с кого спрашивать, но в систему не входят.

Граница проходит по периметру системы: проекты с пометкой «ограниченный доступ» не
уходят ни в Google, ни в Telegram, ни в экспорт
([ADR-0007](docs/adr/ADR-0007-restricted-data.md) в редакции ADR-0011).

## Технологии

| Слой | Выбор |
|---|---|
| Backend | Python 3.12, FastAPI, SQLAlchemy 2 (async), Pydantic v2 |
| База данных | PostgreSQL 16, схема `orbita`, `pg_trgm` + `unaccent` для поиска |
| Фоновые задачи | Redis + ARQ (напоминания, эскалация, отчёты) |
| Frontend | React 18 + TypeScript, Vite, TanStack Query/Table, react-i18next |
| Файлы | S3-совместимое хранилище (MinIO) |
| Качество | ruff, mypy, import-linter, eslint, prettier, pytest, vitest |

Стек совпадает со стеком ассистента SETA — чтобы обе системы поддерживала одна команда.
Обоснование: [ADR-0002](docs/adr/ADR-0002-tech-stack.md).

## Быстрый старт

Нужны: Python 3.12, Node.js 22, Docker, [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/yuldoshbek/Project_.git orbita
cd orbita
cp .env.example .env
```

Дальше — на Linux и macOS через `make`, на Windows через `.\make.ps1` (цели одинаковые):

Linux и macOS:

```bash
make install    # зависимости backend и frontend
make up         # postgres, redis, minio, почта — с ожиданием готовности
make test       # pytest и vitest
make check      # ruff, mypy, границы слоёв, eslint, tsc, prettier
```

Windows (`make` в системе нет, обёртка делает то же самое):

```powershell
.\make.ps1 install
.\make.ps1 up
.\make.ps1 test
.\make.ps1 check
```

`make up` поднимает окружение и ждёт, пока все сервисы пройдут healthcheck. Что появляется:

| Сервис | Адрес | Зачем |
|---|---|---|
| PostgreSQL 16 | `127.0.0.1:55432`, базы `orbita` и `orbita_test` | данные; расширения `pg_trgm`, `unaccent`, `citext`, `pgcrypto` включены при создании |
| Redis 7 | `127.0.0.1:56379` | очередь фоновых задач |
| MinIO | http://localhost:59001 (консоль), логин `orbita` / `orbita-secret` | хранилище вложений, бакет `orbita` |
| Почта (Mailpit) | http://localhost:58025 | письма разработки не уходят наружу |

**Порты смещены намеренно.** Стандартный 5432 часто занят нативным PostgreSQL: контейнер
тогда садится только на IPv6, а клиент молча уходит в чужую базу. Все порты
переопределяются в `.env`, привязка — только к `127.0.0.1`.

**Адрес — `127.0.0.1`, а не `localhost`.** Windows резолвит `localhost` сначала в `::1`;
контейнеры слушают только IPv4, и подключение занимает 2 секунды вместо 70 миллисекунд.
Разницу платит каждое соединение приложения, а не только тесты.

Остановить: `make down` (данные сохраняются) или `make reset` (данные удаляются, база
создастся заново). Полный список целей — `make help`.

Цели `migrate`, `seed` и `dev` заработают вместе с тикетами ORB-003 (приложение) и
ORB-004 (миграции).

## Решения, определяющие проект

- **Две роли вместо разграничения по проектам**
  ([ADR-0011](docs/adr/ADR-0011-two-user-scope.md)). Механизм, у которого нет двух
  сторон, ничего не разграничивает, но стоит дорого. ADR-0003 отменён.
- **Свой Telegram-бот, а не ожидание SETA**
  ([ADR-0013](docs/adr/ADR-0013-telegram-bot.md)): у SETA пока нет API, а канал нужен с
  первого дня. Порт сохранён — реализация подменится без переписывания.
- **Двусторонняя синхронизация в отдельный календарь**
  ([ADR-0012](docs/adr/ADR-0012-google-calendar-sync.md)), не в основной: его можно
  отключить одним переключателем, не задев записи руководителя.
- **«Просрочена» — вычисляемый признак, а не статус**
  ([ADR-0004](docs/adr/ADR-0004-overdue-is-computed.md)).
- **Не вариант A и не вариант B, а «A-ready»**
  ([ADR-0001](docs/adr/ADR-0001-architecture-variant.md)): самостоятельный сервис,
  спроектированный под слияние с SETA, но не зависящий от её сроков.

## Как вести работу

```
/council → /grill → /to-spec → /to-tickets → worktrees + параллельные агенты
        → /tdd → /implement → /verify → /code-review → /finish-branch
```

Один тикет — одна ветка — одно рабочее дерево. Готовность подтверждается прогоном
`make check` и `make test`, а не словами. Подробно: [docs/PIPELINE.md](docs/PIPELINE.md).
