# ORBITA

Рабочее пространство аппарата заместителя директора Агентства космических исследований и
технологий «Ўзбеккосмос». Пользователей двое: помощник вносит данные, заместитель
директора смотрит с iPhone и принимает решения.

Система отвечает руководителю на один вопрос: **что требует моего внимания сейчас и какое
решение я принимаю**. Всё остальное подчинено двум свойствам: картина читается за полминуты
с телефона, а ввод стоит секунды — что можно вычислить, вычисляется.

## Что осталось — шаги заказчика

1. **Площадки и ключи** — ключи вводит только заказчик: мастер `bash scripts/setup-wizard.sh`
   в Git Bash из корня ([SETUP](docs/SETUP.md), 20–30 минут) — Neon, Vercel, Netlify,
   секреты GitHub, ключ уведомлений. До первой выкладки — ответ на V10 (тариф Vercel).
2. **Правила `main`** — импорт [main.json](.github/rulesets/main.json) (SETUP, шаг 3; мастер
   предлагает это последним шагом). На GitHub правила пока не включены.
3. **Первая выкладка** — Actions → «Выкладка» → Run workflow → действие `deploy`, галочка
   «Применять миграции» (SETUP, шаг 4). Затем Actions → «Копия базы» → Run workflow: прогон
   должен создать снимок и назвать число таблиц в схеме.
4. **Вход и уведомления** — первая ссылка, перевыпуск своей, ссылка руководителю,
   уведомления на его iPhone (SETUP, шаг 5).
5. **Настоящие данные** — только в рабочем контуре: таблицы Ижро загружает помощник в
   разделе «Ижро», вкладка «Загрузка»; в репозиторий они не кладутся
   ([data/README](data/README.md)). Версиям презентаций в облаке нужно S3‑совместимое
   хранилище — четыре переменные `ORBITA_S3_*` в Vercel ([.env.example](.env.example), V44);
   без них загрузка презентации честно отказывает, остальное работает.
6. **Приёмка блоков 0–3** — по критериям [PLAN](docs/PLAN.md), на превью и в рабочем
   контуре; что смотреть — раздел 6 каждого отчёта. Ответы на
   [открытые вопросы](docs/OPEN-QUESTIONS.md), замечания — одним пакетом.
7. **Позже — переезд** на сервер агентства по [RUNBOOK](docs/RUNBOOK.md).

| Раздел | Вопрос |

| Идеи и карты | что предложено и как это связано |
| Календарь | что и когда наступит, где тесно |
| Управление | где данные отстали от жизни, из чего выбирают в формах и кто может войти |

Поверх разделов: **Захват** — кнопка (+) с любого экрана. **Утренняя сводка** —
уведомление руководителю на iPhone в 08:30; что в нём будет и дошло ли — вкладка «Сводка»
Пульта. **Монитор** — над лестницей Пульта пять панелей: главные вопросы Ижро, Докладов и
мероприятий, Взаимодействия, Идей и Календаря; кнопка «Совещание» на ноутбуке и мониторе
проводит повестку по одному вопросу на экран. **Отчёты** — неделя и месяц (вкладка
«Отчёт» Пульта) и справка Ижро печатаются в PDF. **Языки** — русский, узбекский латиницей и
кириллицей; содержание поручений Ижро не переводится.

## Запуск

Нужны Docker, [uv](https://docs.astral.sh/uv/) и Node.js 22; `.env` — копия `.env.example`,
чего в нём не хватает, скажет `make doctor`.

```bash
make doctor        # проверить машину: инструменты, .env, контейнер, порты, миграции
make install       # зависимости backend и frontend
make up            # PostgreSQL для разработки, порт 55433
make migrate       # alembic upgrade head
make seed          # справочники
make demo          # вымышленные данные — только для разработки
make dev           # backend :8000, frontend :5173
make test          # pytest + vitest
make e2e           # Playwright на своём стенде: свежая база orbita_e2e, API :8001, сборка :5174
make check         # ruff, mypy, import-linter, eslint, stylelint, tsc, prettier и документы
make docs          # только проверка документов
make job n=morning-summary   # задача по расписанию вручную
make reqs          # backend/requirements.txt из uv.lock — после обновления зависимостей
```

На Windows: `./make.ps1 <цель>`, у `job` имя задачи вторым словом. Стенд `make e2e` окно
`make dev` и его базу не трогает.

## Размещение

**Облако — рабочий контур сейчас** ([ADR-0028](docs/adr/ADR-0028-hosting.md)); площадки
настраиваются по [SETUP](docs/SETUP.md). Интерфейс на Netlify проксирует `/api` на Vercel
(Франкфурт); PostgreSQL — Neon, ветки `production` и `demo`; файлы — S3‑совместимое
хранилище по подписанным ссылкам (допущение V44); задачи по расписанию — GitHub Actions
([ADR-0035](docs/adr/ADR-0035-scheduler-on-github-actions.md)). Каждый PR получает
превью со своей веткой базы от демо — настоящих данных там нет. Выкладка — по кнопке, с
проверкой коммита и откатом; снимок базы — каждую ночь в 01:00 по Ташкенту, хранится неделю.

**Сервер агентства — подготовлен** ([deploy/server](deploy/server)). Тот же код в четырёх
контейнерах: PostgreSQL, API (миграции и справочники при старте), Caddy (интерфейс, HTTPS,
прокси `/api`), cron с тем же расписанием, что `jobs.yml`; файлы — на диске сервера,
ночная копия — `backup.sh`. Стек поднят 05.10 на машине разработки на копии базы (критерий 5 блока 3).
Нужны Docker Compose v2, доменное имя и сертификат, которому доверяет iPhone; порядок — в
[RUNBOOK](docs/RUNBOOK.md).
