## 1. Зачем система

Заместитель директора отвечает за исполнение поручений вышестоящих органов, за проекты
агентства и за работу учреждённого агентством Центра космического мониторинга (МЧЖ).
Данных много, они разбросаны по таблицам Word, письмам и головам. Руководитель узнаёт о
срыве, когда срок уже прошёл.

ORBITA собирает всё это в одно место и отвечает руководителю на один вопрос: **что
требует моего внимания сейчас и какое решение я принимаю**.

Два свойства продукта определяют всё остальное.

1. **Презентационный слой — это и есть система.** Если руководитель не понял картину за
   полминуты с телефона, задача не выполнена, сколько бы функций ни работало.
2. **Стоимость ввода определяет, выживет ли продукт.** Данные вносит один человек между
   делом. Всё, что можно вычислить, вычисляется, а не вводится. Новое поле появляется
   только вместе с критерием приёмки, который без него не проверить.

### 1.1. Пользователи

| | Помощник | Руководитель |
|---|---|---|
| Что делает | вносит и поддерживает данные, загружает таблицы Ижро, готовит доклады, ведёт обход | смотрит, анализирует, принимает решения, меняет сроки и приоритеты, ведёт свои идеи и карты |
| Где работает | ноутбук — основное; телефон — захват на ходу | iPhone — основное; ноутбук и большой монитор — разбор и совещания |
| Ограничений между ними нет | оба видят всё | все действия попадают в журнал, видно, кто что изменил |

Сотрудники агентства и Центра, которым поручают работу, **в систему не входят**. Они
живут в справочнике как ответственные.

### 1.2. Чего система не делает

Не делаем сейчас и не закладываем «на будущее»: ЭЦП и электронный документооборот,
бухгалтерский учёт, учёт трудозатрат в часах, разграничение доступа между пользователями,
публичный портал, мобильное приложение в магазинах (система ставится как PWA), обращение
к внешним моделям ИИ, конструктор отчётов, собственный Telegram‑бот, ведение всей
переписки агентства.

## 2. Разделы

Десять разделов. У каждого один вопрос, на который он отвечает.

| Раздел | Вопрос |
|---|---|
| Пульт | Что требует внимания сейчас по всем разделам? |
| Программы | Где мы по многолетним программам и что должно случиться до конца года? |
| Проекты | Где мы по каждому проекту и подпроекту? |
| Задачи | Что делать, кому и к какому сроку? |
| Ижро | Что на контроле, что горит, кто исполнитель, работает ли он, из‑за кого сорвётся? |
| Взаимодействие | Кто кого ждёт: организации, письма, соглашения? |
| Доклады и мероприятия | Готовы ли мы к дате и кто задерживает? |
| Идеи и карты | Что предложено и как это связано? |
| Календарь | Что и когда наступит, где тесно? |
| Управление | Справочники, загрузка, обход, ссылки доступа (только помощник) |

Отдельного раздела «Аналитика» нет: у каждого раздела свои виджеты‑вопросы, Пульт их
собирает, отчёт недели и месяца живёт вкладкой Пульта.

## 3. Предметная модель

Ниже перечислено то, что система хранит. Поля, не упомянутые здесь, не заводятся.
Общие поля у всех записей: идентификатор, кто и когда создал и изменил.

### 3.1. Программы и проекты

**Проект** — работа агентства с целью, сроком, вехами и одним ответственным.

| Поле | Смысл |
|---|---|
| название, описание | |
| тип | из справочника типов (3.9), у типа свой шаблон вех |
| родительский проект | одна ступень вложенности: у программы есть подпроекты |
| многолетняя | признак программы: показывается в разделе «Программы» |
| начало, срок | плановые даты |
| исходный срок | первое значение срока; ведётся системой, не человеком |
| статус | в работе, на паузе, завершён, отменён |
| ответственный | сотрудник |
| организации и их роли | заказчик, исполнитель, соисполнитель, головное ведомство |
| направление, регион | необязательные; регион — из 14 |
| что мешает | одна строка с датой обновления |
| готовность | процент, считается по закрытым вехам и задачам |

**Веха** — шаг проекта с собственным сроком: название, срок, исходный срок, порядок,
признак «пройдена», дата прохождения. Вехи подставляются из шаблона типа и правятся.

**Годовой цикл** — повторяющийся срок («ежегодно в феврале», «ежеквартально», «раз в три
года»). Система разворачивает его в конкретные даты на год вперёд.

### 3.2. Задачи

Название, тип (3.9), ответственный, срок, исходный срок, статус (новая, в работе, на
проверке, готова, отменена), чек‑лист, привязка к проекту, поручению, письму или
подготовке — любая из них необязательна. Задача без привязки — обычное дело.

### 3.3. Ижро

**Документ** — вид (ПФ, ПҚ, ЎРҚ, ВМҚ, фармойиш, баён), номер, дата, название, тема.
Опознаётся видом, номером и датой **вместе**: номера повторяются в разных годах.

**Поручение** — пункт документа:

| Поле | Смысл |
|---|---|
| документ, пункт, порядок пункта | |
| содержание, механизм исполнения | как в источнике, на узбекской кириллице; переводу не подлежит |
| срок, точность срока, откуда взят год | точность: точный день, месяц, конец года |
| промежуточный срок | середина срока, если срок длиннее трёх месяцев |
| исходный срок и история продлений | было → стало, дата, партия привоза, вид переноса |
| ответственный (как в таблице) и сопоставленный сотрудник | сырое написание хранится всегда |
| головной исполнитель | организация; если не агентство — мы соисполнитель |
| этап | не начато, в работе, сдано, возвращено на доработку, снято с контроля |
| запрошено продление | признак |
| проблема и предложение | для доклада наверх, с датой обновления |
| источник и партия привоза | АП, Кабмин, законодательные акты; файл, дата, отпечаток |

**Контрольная отметка** — запись помощника: вид (связался, делает, не отвечает),
обещанная дата, комментарий, дата.

**Связь поручения** с проектом, задачей или письмом: основание, подтверждение, связано.
Состояние поручения из связанных задач **не выводится**: задачи дают только сигналы
расхождения.

### 3.4. Организации, письма, соглашения

**Организация** — название, короткое имя, вид (министерство, ведомство, хокимият,
международная организация, компания), признак «учреждена агентством» (Центр), контакты.

**Письмо** — направление (входящее, исходящее), организация, тема, дата, номер, срок
ответа, наш автор, связь с проектом, поручением или подготовкой, вложение, дата ответа,
ссылка на ответное письмо, **оценка ответа** руководителем (по существу, формально, не по
сути).

Вносятся только письма, где нужен ответ или действие руководителя либо стоит срок.

**Соглашение** — организация, вид (меморандум, договор), дата, срок, следующий шаг и его
дата, ответственный.

### 3.5. Подготовка: доклады и мероприятия

**Подготовка** — общая основа: вид (доклад, мероприятие), название, дата показа или
проведения, дата «начать готовить», ответственный за сборку, этап подготовки (тезисы,
сведения, черновик, согласование, репетиция, показ), чек‑лист, связь с программой или
проектом.

У доклада дополнительно — **адресат**: Кабинет министров, Администрация Президента,
Президент, Премьер‑министр, иное.

**Запрос сведений** — что нужно, от кого (сотрудник или организация), срок, статус
(запрошено, получено, просрочено), дата получения, вложение.

**Версия презентации** — номер, файлы (PDF для просмотра, исходник), кто загрузил, когда,
статус (на просмотре, на доработке, принята).

**Замечание** — версия, номер слайда, текст, автор, дата, отметка «исправлено» и в какой
версии.

### 3.6. Идеи и карты

**Идея** — текст, автор, шаг (набросок, на рассмотрении, решено), решение (проект,
задача, отложено), ссылка на созданный объект, дата.

**Карта** — название, режим (набросок, структура), узлы и связи. Узел: текст, координаты,
родитель, ссылка на проект или задачу, если узел связан с настоящим объектом.

### 3.7. Решения руководителя

Объект, вид (утвердить, вернуть, поручить, поторопить, эскалировать, просить продление,
отклонить), текст, ответственный за исполнение, срок, состояние (открыто, выполнено,
просрочено), дата.

### 3.8. Люди, доступ, журнал

**Сотрудник** — ФИО, должность, подразделение, организация (агентство или Центр),
контакты, активен; псевдонимы написаний ФИО, подтверждённые человеком.

**Пользователь** — роль (помощник, руководитель), язык, устройство для уведомлений;
**ссылка доступа**: хранится только отпечаток, видна дата выпуска и последнего входа, есть
перевыпуск.

**Журнал изменений** — кто, что, когда, было и стало по каждому полю. Пишется сервисным
слоем в одной транзакции с изменением.

### 3.9. Справочники (редактируются помощником, не кодом)

Типы проектов с шаблонами вех, типы задач, виды документов, источники Ижро, виды связей,
направления, регионы, организации, пороги сигналов.

**Типы проектов:** цикл мониторинга, нормативный акт, стандарт, платформа или ИТ,
спутниковая миссия, пилот с отраслью, заказ услуги, международное сотрудничество, кадры и
образование, заказ вышестоящего органа.

**Типы задач:** ТЗ, рассмотрение и визирование, согласование, внесение в Кабмин,
аналитическая информация, выезд на место, запрос или опросник, выгрузка в субплатформу,
отбор участников, подготовка сведений по Ижро, прочее.

## 4. Сигналы и расчёты

Все показатели считает **один сервис**. Экран, отчёт, уведомление и сценарий «что если»
берут числа только у него.

| Сигнал | Правило |
|---|---|
| Просрочено | срок прошёл, состояние не терминальное. **Вычисляется, не хранится** |
| Горит | до срока не больше порога (по умолчанию 7 дней), работа не закрыта |
| Молчит | нет движения дольше порога (по умолчанию 14 дней) |
| Ждёт решения | у объекта есть открытый вопрос к руководителю |
| Зависит от чужих | головной исполнитель — не агентство, и с его стороны нет движения |
| Признак жизни | самое свежее из: контрольная отметка, движение связанной задачи, промежуточная информация |
| Отклонение | число дней: просрочки, ожидания решения, молчания, отставания от плана |
| Отставание от плана | доля прошедшего времени минус готовность, переведённая в дни |
| Успеваем? | фраза по темпу закрытия; при менее чем 10 закрытых задачах — «мало данных» |
| Скорость ответа | дни от письма до ответа; по организации — только при пяти письмах и больше |
| С прошлого визита | изменения с момента предыдущего входа руководителя |

**Лестница внимания** — единый порядок строк из всех разделов:

**ждёт решения → просрочено → горит → зависит от чужих → молчит → по плану.**

Норма сворачивается в строку «и ещё N по плану». Порядок задаёт сервер, вручную строки не
сортируются.

Пороги лежат в справочнике и меняются без разработчика.

## 5. Аналитика

**Правило.** Показатель попадает на экран, только если у него есть: вопрос руководителя в
заголовке, ответ одним числом или фразой, дата актуальности данных и действие — переход к
отфильтрованному списку или кнопка. Если решение назвать нельзя, показателя нет.

**Запрещено:** метрики, которые только растут («закрыто задач всего»); проценты готовности
без оси времени; сводные индексы здоровья; средние по выборке меньше пяти; графики,
рисующие журнал изменений; пустые данные, показанные как нули; одно и то же число в трёх
местах.

Каталог вопросов по разделам:

| Раздел | Вопрос | Ответ и действие |
|---|---|---|
| Пульт | Что ждёт моего решения? | число и старейшее ожидание; кнопки решения прямо в строке |
| Пульт | Что сорвётся за 14 дней? | список со сроками; вмешаться, перенести, поручить |
| Пульт | Что изменилось с моего прошлого визита? | строка изменений |
| Пульт | Держим ли мы свои сроки? | число переносов и суммарный сдвиг; переутвердить срок |
| Программы | Что должно случиться до конца года? | список вех с отсчётом |
| Программы | Успеваем ли к дате программы? | фраза с правилом; урезать объём или перенести |
| Проекты | Идёт или стоит? | дни без движения; позвонить ответственному |
| Проекты | Что мешает и кто может снять? | строка «что мешает» с возрастом |
| Проекты | Что держит Центр? | проекты Центра с отклонением |
| Задачи | Кто перегружен? | просрочки по ответственным |
| Ижро | Что горит и что просрочено? | два числа; кого поторопить |
| Ижро | Что сорвётся из‑за чужого ведомства? | по ведомствам; письмо или звонок |
| Ижро | Работает ли ответственный? | «молчит N дн» при близком сроке; контрольная отметка |
| Ижро | Как исполнен документ целиком? | стена документов; кого вызвать с отчётом |
| Ижро | Где продлевают хронически? | «исходный → текущий», ≥ 2 переносов |
| Ижро | Хватит ли сил на декабрь? | наступает против закрытого; начинать заранее |
| Ижро | Что докладывать наверх? | поручения с проблемой; собрать справку |
| Взаимодействие | Кто нам не отвечает? | исходящие без ответа по организациям |
| Взаимодействие | На что мы должны ответить? | входящие со сроком |
| Взаимодействие | Как быстро отвечают? | медиана дней по организации |
| Взаимодействие | Какие соглашения спят? | нет движения больше 90 дней |
| Доклады | Готовы ли к дате и кто задерживает? | «не хватает N сведений; X задерживает M дн»; напомнить |
| Идеи | Что ждёт моего «да»? | идеи на рассмотрении по возрасту |
| Календарь | Где неделя перегружена? | «24.09 — 3 срока и мероприятие» |

Формы визуализации — только знакомые: список, полоса, линия времени, календарь, стена
документов. Орбитальный обзор допускается **только** на большом мониторе и только рядом с
линейным видом.

## 6. Экраны и устройства

Логика отличается не оформлением, а набором функций.

| | Телефон 390 × 844 | Ноутбук 1440 × 900 | Монитор 2560 × 1440 |
|---|---|---|---|
| Руководитель | решить, увидеть, что горит и что изменилось, записать идею | разбор проекта, поручения, документа | обзор всего; режим «Совещание»: один вопрос на экран |
| Помощник | захват, контрольная отметка, смена статуса, мини‑обход | основное рабочее место: ввод, таблицы, загрузка, «что если», сборка доклада, обход | листает, фиксирует решения |
| Навигация | нижняя панель: Пульт · Календарь · (+) · Поиск · Ещё | боковая панель, список и детали рядом | многопанельный обзор |
| Чего нет | таблиц, диаграммы Ганта, полотна карты (карта — контур), тяжёлой графики | — | редактирования |

Общие требования: цель нажатия на телефоне не меньше 44 px; поиск и кнопка захвата на
каждом экране; ничего важного не прячется за наведением мыши.

**Темы.** Светлая — основная. Приглушённая — сланцево‑синяя, не чёрная. По умолчанию тема
следует настройке устройства, переключатель есть. Контраст текста не ниже AA в обеих.

**«Космос»** живёт в движении и акцентах: орбитальные дуги, мягкие частицы в шапке на
ноутбуке и мониторе, плавные переходы, одна вспышка изменившегося числа. Никогда не под
цифрами и текстом. На телефоне — минимум. `prefers-reduced-motion` выключает.

**Языки.** Русский — основной. Узбекская латиница и кириллица добавляются; ни одной
строки текста в коде, только ключи. Содержание поручений не переводится.

## 7. Ввод данных

- **Захват** — одна кнопка на каждом экране: текст, диктовка телефона, фото. Тип
  выбирается одним касанием: идея, задача, письмо, мероприятие, просьба руководителя.
- **Разбор строки.** «к пятнице рассмотрение проекта постановления Минэкологии, Каримов»
  превращается в тип, срок и ответственного. Разбор правилами, без внешних моделей.
- **Обязательных полей минимум:** у задачи — название; у проекта — название и тип.
  Остальное подставляется из типа, из места добавления или остаётся пустым.
- **Загрузка Ижро.** Файл Word перетаскиванием. Предпросмотр показывает классы изменений:
  новые, без изменений, текст изменился, сменился ответственный, срок сдвинут, исчезли,
  не распознано. Применение идемпотентно: повторная загрузка того же файла ничего не
  меняет. Перенос срока подтверждает человек, и он попадает в историю продлений.
- **Сопоставление ФИО** подтверждает человек. Алгоритм только предлагает, псевдоним
  запоминается. Однофамильцы с разными инициалами не склеиваются.
- **Обход** — еженедельная очередь того, где данные могли отстать: у каждого пункта
  причина «почему вы здесь» и два‑три действия в одно касание. Кнопки «всё нормально» нет.

## 8. Уведомления

- **Утренняя сводка** в 08:30 по Ташкенту: что ждёт решения, что горит сегодня.
- **Пуш** только на два события: появилось «ждёт вашего решения»; наступил срок сегодня.
- Канал — уведомления PWA. На iPhone работают после установки на экран «Домой»: система
  показывает, как это сделать.
- Уведомления идемпотентны: повторный запуск задачи не шлёт второго сообщения.

## 10. Интеграции

- **Ижро** — файлами Word, вручную или по запросу у ответственного сотрудника. API у
  системы нет.
- **SETA** — пока не подключается. В архитектуре есть порт: события по поручениям
  (принято, начато, сдано, продлено) станут ещё одним признаком жизни, когда SETA отдаст
  API. Подключение не меняет расчётов.
- **Экспорт**: справка по проблемным поручениям и отчёт недели и месяца — PDF; презентации
  хранятся файлами как есть.

## 12. Допущения и открытые вопросы

Принятые допущения (меняются ответом заказчика):

1. «25 <месяц>» в таблице Ижро — это срок поручения.
2. При продлении в таблице меняется ячейка срока; перенос система замечает сама.
3. Возвраты на доработку бывают и показываются руководителю.
4. Промежуточный срок считается автоматически для поручений длиннее трёх месяцев.
5. Качество ответа на письмо — отметка руководителя в одно касание.
6. Скорость ответа по организации показывается при пяти письмах и больше.

Живые вопросы ведутся в [docs/OPEN-QUESTIONS.md](../docs/OPEN-QUESTIONS.md). Реализация,
упершаяся в неотвеченный вопрос, не угадывает: вопрос дописывается туда, работа идёт по
зафиксированному допущению.
