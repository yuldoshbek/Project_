# Рабочие деревья git

Один тикет — одна ветка — одно рабочее дерево. Агенты, работающие в одном каталоге,
перетирают файлы друг друга и путают вывод тестов; worktree решает это без клонирования
репозитория заново.

## Где размещать

Рабочий каталог проекта — `D:\Проектная карта` — содержит пробел и кириллицу. Часть
инструментов (docker-compose, некоторые python-скрипты в Windows) на таких путях ведёт себя
непредсказуемо. Поэтому деревья создаём по ASCII-пути **вне** репозитория:

```bash
git worktree add -b orb-014-tasks-crud /d/orbita-wt/orb-014 main
```

Каталог `/d/orbita-wt/` не должен находиться внутри репозитория: вложенное дерево ломает
`git status` в основном.

## Порядок работы

1. Обнови базу и создай дерево:
   ```bash
   git fetch origin && git worktree add -b orb-NNN-слаг /d/orbita-wt/orb-NNN origin/main
   ```
2. Перейди в дерево и подготовь окружение. Общие для всех деревьев `postgres`, `redis`,
   `minio` поднимаются **один раз** из основного каталога (`make up`) — не поднимай второй
   набор контейнеров на тех же портах. Для тестов каждому дереву нужна своя тестовая база:
   ```bash
   export ORBITA_TEST_DB=orbita_test_orb_NNN
   ```
3. Установи зависимости в дереве (`.venv` и `node_modules` не разделяются между деревьями).
4. Работай, коммить, запускай тесты внутри дерева.
5. После слияния — убери за собой.

## Уборка

```bash
git worktree list
git worktree remove /d/orbita-wt/orb-NNN
git branch -d orb-NNN-слаг
git worktree prune
```

Если `remove` отказывается из-за незакоммиченных изменений — сначала разберись, что это за
изменения. `--force` здесь означает потерю работы.

## Чего избегать

- **Не создавать дерево на уже существующей ветке**, которая занята другим деревом: git
  откажет, и правильно сделает.
- **Не работать над двумя тикетами в одном дереве.** Смешанный диск невозможно ни
  отревьюить, ни откатить по частям.
- **Не создавать миграции Alembic параллельно в двух деревьях одной волны** — см. правило 1
  в [INDEX.md](../../../docs/tickets/INDEX.md). Расходящиеся `down_revision` придётся
  разбирать вручную.
- **Не забывать `git fetch` перед созданием дерева**: дерево от устаревшего main гарантирует
  конфликт при слиянии.

## Проверка перед сдачей тикета

```bash
git worktree list          # лишних деревьев нет
git -C /d/orbita-wt/orb-NNN status   # чисто
```
