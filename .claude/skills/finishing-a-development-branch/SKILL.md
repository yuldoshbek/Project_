# Завершение блока

Блок закончен не тогда, когда код написан, а тогда, когда он слит, выложен и заказчик
увидел его на своих данных.

## Предусловия

- `/verify N` пройден: `make check`, `make test`, `make e2e` зелёные, вывод приложен;
- отчёт `docs/reports/BLOCK-N.md` написан;
- все критерии приёмки блока из [PLAN](../../../docs/PLAN.md) закрыты или явно названы
  незакрытыми в отчёте.

## Порядок

1. **История коммитов.** Сообщения по-русски, в повелительном наклонении, с префиксом
   блока: `B1: Добавить раздел «Проекты»`. Мусорные коммиты («fix», «wip») вычищаются.
2. **Синхронизация с `main`.** Подтянуть и разрешить конфликты у себя, а не в PR.
3. **Миграции.** `alembic heads` — одна голова. `alembic check` — схема совпадает с
   моделями. Проверить `upgrade` → `downgrade` → `upgrade` на ветке демо‑базы.
4. **PR** с описанием: что сделано, какие критерии закрыты, ссылка на отчёт и на превью.
   Проверки обязательны и должны быть зелёными.
5. **Приёмка.** Заказчик смотрит превью, даёт замечания одним пакетом. Правки — в этой же
   ветке, пока приёмка не пройдена.
6. **Слияние в `main`** и **выкладка в рабочий контур по кнопке**. После выкладки —
   проверка на живой системе: открыть с телефона по личной ссылке.
7. **Уборка.** Ветка удаляется, план дополняется записью в журнале изменений, отчёт
   остаётся в `docs/reports/`.

## Чего не делать

- Не сливать с красными проверками и не отключать их «на разок».
- Не тащить в блок работу следующего блока: она записывается в план, а не делается молча.
- Не выкладывать в рабочий контур без приёмки: там живые поручения.
