# Завершение ветки тикета $1

Выполняется после зелёного `/verify` и пройденного `/code-review`. Не раньше.

## 1. Убедись, что работа действительно закончена

- [ ] `/verify` пройден, вывод приложен.
- [ ] Замечания `/code-review` либо исправлены, либо явно отклонены с обоснованием.
- [ ] Все чекбоксы критериев приёмки отмечены.

## 2. Приведи историю в порядок

```bash
git status
git log --oneline main..HEAD
```

Коммиты должны читаться как рассказ о работе: `ORB-NNN: краткое описание`. Мусорные
коммиты («фикс», «ещё раз», «wip») — склей. Не переписывай историю, если ветку уже кто-то
забрал себе.

## 3. Синхронизируйся с main

```bash
git fetch origin
git rebase origin/main
make check && make test
```

Отдельно проверь миграции: `alembic heads` после rebase должен показывать **одну** голову.
Если голов две — перебазируй свою миграцию на актуальную, не сливай их вручную в БД.

## 4. Слияние

Спроси меня, прежде чем push и открытие PR: это действие наружу.

После подтверждения — push ветки, PR с описанием: что делает тикет, какие критерии
приёмки закрыты, что осталось за границами, какие ADR затронуты.

## 5. Убери за собой

```bash
git worktree list
```

- Удали worktree тикета после слияния (скилл `using-git-worktrees`, раздел «Уборка»).
- Удали слитую ветку локально и на origin.
- Отметь тикет закрытым в `docs/tickets/`.
- Если по ходу работы всплыли вопросы к заказчику — они уже должны быть в
  [OPEN-QUESTIONS](../../docs/OPEN-QUESTIONS.md); проверь, что записаны.
- Если решение отклонилось от ADR — обнови ADR или заведи новый со статусом
  «заменяет ADR-NNNN».

## 6. Что дальше

Посмотри [INDEX.md](../../docs/tickets/INDEX.md): какая волна открылась после этого тикета,
какие тикеты разблокированы. Перед следующим тикетом — `/clear`.
