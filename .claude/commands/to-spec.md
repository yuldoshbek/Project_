# В спецификацию

Предмет: **$ARGUMENTS**

Вход: [ТЗ](../../tz/TZ-ORBITA-v1.0.md), [CONTEXT.md](../../docs/CONTEXT.md),
[ADR](../../docs/adr). Если по предмету не проходил `/grill` — сначала он.

Выход — раздел [SPEC.md](../../docs/SPEC.md) (или отдельный файл в `docs/spec/`, если
раздел крупный), описывающий **что** должно быть построено, без реализационных подробностей.

## Правила

1. **Каждое утверждение проверяемо.** «Быстро» — не спецификация. «p95 не более 400 мс на
   наборе 200 проектов и 3000 задач» — спецификация.
2. **Модель данных с полями и типами**, включая ограничения и индексы, которые следуют из
   требований (фильтр по просрочке требует индекса — это часть спецификации, а не
   оптимизация).
3. **API: метод, путь, назначение, тикет.** Форма ответов и ошибок — по соглашениям из
   SPEC 2, не переизобретай.
4. **Экраны: что пользователь должен смочь сделать**, а не как это выглядит.
5. **Поведение при отказе** описывается наравне с успешным путём.
6. **Явное «не входит».** Спецификация без границ — это спецификация всего.
7. Каждый пункт ссылается на раздел ТЗ или на ADR. Пункт без источника — это выдуманное
   требование; либо найди источник, либо выброси.

## Проверка перед завершением

- [ ] Каждое требование раздела 6 ТЗ по этому блоку отражено или явно вынесено за границы.
- [ ] Ни одно утверждение нельзя понять двумя способами.
- [ ] Разграничение доступа описано для каждой точки выдачи данных.
- [ ] Режим `restricted` (ADR-0007) описан для каждой точки выдачи наружу.
- [ ] Есть числа там, где ТЗ говорит «быстро», «удобно», «несколько».
