# Эпик E1 — MVP: проекты и база задач

Этап 1 ТЗ. Результат — система, в которую уже можно ежедневно вводить данные.

## ORB-010 — Справочники

- Оценка: S · Зависит от: ORB-004 · Блокирует: ORB-011, ORB-014, ORB-035
- Требования ТЗ: 7, 6.8

**Объём.** Модели `directions`, `priorities`, `project_statuses`, `settings`,
`organizations`. Сиды строго из раздела 7 ТЗ на трёх локалях. Чтение через API.

**Критерии приёмки.**
- [ ] Все значения из ТЗ 7 присутствуют после `make seed`, названия заполнены на ru, uz-Cyrl, uz-Latn.
- [ ] Справочные значения нигде не захардкожены в коде как перечисления, кроме технических кодов.
- [ ] Деактивация значения справочника не ломает существующие записи, но скрывает его из форм создания.

## ORB-011 — Проекты: модель и CRUD

- Оценка: L · Зависит от: ORB-008, ORB-010 · Блокирует: ORB-012, ORB-013, ORB-018, ORB-019, ORB-025, ORB-029
- Требования ТЗ: 6.1 · Решения: ADR-0003, ADR-0007, ADR-0005

**Объём.** Таблица `projects` со всеми полями из SPEC 1.3, генерация `code`, CRUD API,
фильтрация и сортировка, вычисление светофора и `progress_pct` в режиме `auto`,
валидация: `due_on` не раньше `started_on`, причина обязательна для статусов
«Приостановлен» и «Отменён», мини-проект не требует вех.

**Критерии приёмки.**
- [ ] Создание, чтение, изменение, удаление проекта работают для куратора и запрещены посторонним.
- [ ] Смена статуса на «Приостановлен» без причины отклоняется с понятной ошибкой.
- [ ] Светофор в ответе совпадает с правилом ADR-0005 (табличный тест на граничных датах).
- [ ] `progress_pct` в режиме `auto` пересчитывается при смене статуса задачи.
- [ ] Каждое изменение попало в `audit_log`.

## ORB-012 — Вехи проекта

- Оценка: S · Зависит от: ORB-011 · Блокирует: ORB-026, ORB-031 · Требования ТЗ: 6.1

**Критерии приёмки.**
- [ ] Веха создаётся, переупорядочивается, помечается выполненной.
- [ ] Веха с прошедшим сроком и статусом `planned` автоматически считается `missed` в выдаче.
- [ ] Для мини-проекта вехи необязательны и раздел скрыт.

## ORB-014 — Задачи: модель и CRUD

- Оценка: L · Зависит от: ORB-008, ORB-010, ORB-011 · Блокирует: ORB-015..ORB-024, ORB-029, ORB-038
- Требования ТЗ: 6.2, 7 · Решения: ADR-0004

**Объём.** Таблица `tasks` из SPEC 1.4, генерация `code`, CRUD, фильтры (исполнитель,
куратор, проект, направление, приоритет, статус, срок), сортировки, вычисляемые
`is_overdue` и `days_overdue`, задача вне проекта, признак `is_control`.

**Критерии приёмки.**
- [ ] Задача создаётся как внутри проекта, так и вне его.
- [ ] `is_overdue` считается по ADR-0004; смена статуса на «Выполнена» снимает просрочку.
- [ ] Фильтр «просроченные» использует индекс `(status, due_at)` — подтверждено `EXPLAIN`.
- [ ] Задача недоступна пользователю, не имеющему доступа к её проекту.
- [ ] Переходы статусов валидируются: из `done` нельзя вернуться в `new` минуя `in_progress`.

## ORB-016 — Комментарии

- Оценка: M · Зависит от: ORB-011, ORB-014 · Блокирует: ORB-033 · Требования ТЗ: 6.1, 6.2

**Критерии приёмки.**
- [ ] Комментарий добавляется к проекту и к задаче, редактируется автором, мягко удаляется.
- [ ] Упоминание сотрудника порождает уведомление (заглушка до ORB-037).
- [ ] Лента комментариев и история изменений показываются одним хронологическим потоком.

## ORB-017 — Вложения и версии

- Оценка: L · Зависит от: ORB-011, ORB-014 · Блокирует: ORB-033, ORB-043
- Требования ТЗ: 6.6 · Решения: ADR-0009 · Открытый вопрос: Q7

**Критерии приёмки.**
- [ ] Повторная загрузка файла с тем же именем создаёт версию, а не второй документ.
- [ ] Одинаковый по содержимому файл (совпадает sha256) не создаёт новую версию.
- [ ] Файл раздаётся presigned-ссылкой с ограниченным временем жизни, не через приложение.
- [ ] Превышение лимита размера и запрещённый тип отклоняются с понятным сообщением.
- [ ] Предпросмотр PDF и изображений работает; для DOCX и XLSX создаётся производный PDF.

**Критерии приёмки.**
- [ ] Показаны статус, светофор, процент выполнения, вехи, задачи, файлы, партнёры, лента событий.

## ORB-023 — Мастер создания проекта и задачи, шаблоны

- Оценка: M · Зависит от: ORB-018, ORB-022 · Требования ТЗ: 6.1, 10.5, 2.4, сценарий U1

**Критерии приёмки.**
- [ ] От нажатия «Создать» до сохранения — не более 3 шагов.
- [ ] Шаблоны проектов из ТЗ 6.1 преднастраивают направление, приоритет и вехи.
- [ ] Замер: создание проекта с вехами и вложением — не более 120 секунд у неподготовленного пользователя.
- [ ] Черновик не теряется при случайном закрытии формы.

## ORB-024 — Массовые операции над задачами

- Оценка: S · Зависит от: ORB-020 · Требования ТЗ: 6.2

**Критерии приёмки.**
- [ ] Перенос срока, смена исполнителя и смена статуса применяются к выбранным задачам одной операцией.
- [ ] Операция атомарна: при отказе по одной задаче не применяется ни одна, ошибка называет причину.
- [ ] В аудит попадает запись по каждой изменённой задаче.

---

## ORB-025 — Архив проектов

- Оценка: S · Зависит от: ORB-011, ORB-019 · Требования ТЗ: 6.1

**Критерии приёмки.**
- [ ] Завершённые и отменённые проекты уходят в архив и исчезают из основных списков.
- [ ] Архив доступен поиску и фильтрам, проект восстанавливается в активные.
- [ ] Архивный проект доступен только для чтения, пока не восстановлен.
