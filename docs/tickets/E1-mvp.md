## ORB-010 — Справочники ✅

- Оценка: S · Зависит от: ORB-004 · Блокирует: ORB-011, ORB-014, ORB-035
- Требования ТЗ: 7, 6.8 · **Статус: закрыт.** Ветка `orb-010-dictionaries`

**Объём.** Модели `directions`, `priorities`, `project_statuses`, `settings`,
`organizations`. Сиды строго из раздела 7 ТЗ на трёх локалях. Чтение через API.

**Критерии приёмки.**
- [x] Все значения из ТЗ 7 присутствуют после `make seed`, названия заполнены на ru,
      uz-Cyrl, uz-Latn — проверено тестом по каждому справочнику отдельно и вручную
      на живом сервере.
- [x] Справочные значения не захардкожены, кроме технических кодов. Разделение
      описано в `app/domain/dictionaries.py`: код принадлежит коду, название,
      порядок, цвет и видимость — данным.
- [x] Деактивация значения не ломает существующие записи, но скрывает его из форм:
      параметр `active_only` разделяет эти два случая.

**Разрешённое противоречие ТЗ.** Раздел 6.8 требует менять справочники без
разработчика, разделы 6.4 и 6.5 — чтобы система понимала смысл статусов. Полностью
редактируемый справочник этого не даёт: смысл нового значения системе неоткуда взять.
Переименовать «На контроле руководителя» можно из интерфейса и на всех трёх
письменностях; завести седьмой статус проекта — нельзя. Ограничение названо вслух.

**Что нашлось по дороге.**
1. **Время в схеме было наивным.** `Mapped[datetime]` без явного
   `DateTime(timezone=True)` даёт `timestamp without time zone` — прямое нарушение
   инварианта CLAUDE.md, невидимое ни в модели, ни на ревью. Исправлено в основании
   модели; добавлена проверка всей схемы `test_no_naive_timestamp_columns`.
2. **Подключение по имени `localhost` стоило 2,1 секунды вместо 70 миллисекунд.**
   Windows резолвит `localhost` сначала в `::1`, а контейнеры слушают только IPv4.
   Платило бы каждое соединение приложения, а не только тесты; списали бы на «система
   тормозит». Везде проставлен `127.0.0.1`; набор тестов ускорился с 55 секунд до 4,7.
3. **`alembic.ini` пришлось перевести на латиницу** (обнаружено в ORB-004) — но
   выяснилось, что кириллица ломает и имена файлов миграций: `%(slug)s` убран из
   шаблона, описание живёт в docstring ревизии.

**Решения сверх карточки.**
- Справочник статусов задачи заведён наравне с остальными — интерфейсу нужны их
  локализованные названия. «Просрочена» в него не входит (ADR-0004), и это
  проверяется тестом.
- Порог жёлтой зоны для «Срочно» хранится значением `warn_days_override = 0`, а не
  условием в коде: по ADR-0005 помощник должен уметь его поправить.
- Сиды **не перезаписывают** существующие строки. Иначе обновление системы затирало
  бы правки помощника, и редактируемый справочник стал бы декорацией.
- Заложена тестовая инфраструктура для всех следующих тикетов: схема накатывается и
  наполняется один раз за прогон, каждый тест работает во внешней транзакции, которая
  откатывается.

## ORB-011 — Проекты: модель и CRUD

- Оценка: L · Зависит от: ORB-053, ORB-010 · Блокирует: ORB-012, ORB-013, ORB-018, ORB-019, ORB-025, ORB-029
- Требования ТЗ: 6.1 · Решения: ADR-0011, ADR-0007, ADR-0005

**Объём.** Таблица `projects` со всеми полями из SPEC 1.3, генерация `code`, CRUD API,
фильтрация и сортировка, вычисление светофора и `progress_pct` в режиме `auto`,
валидация: `due_on` не раньше `started_on`, причина обязательна для статусов
«Приостановлен» и «Отменён», мини-проект не требует вех.

**Критерии приёмки.**
- [ ] Создание, чтение, изменение и удаление проекта доступны помощнику; руководителю
      на запись доступно только решение по проекту (ORB-062, ADR-0011).
- [ ] Смена статуса на «Приостановлен» без причины отклоняется с понятной ошибкой.
- [ ] Светофор в ответе совпадает с правилом ADR-0005 (табличный тест на граничных датах).
- [ ] `progress_pct` в режиме `auto` пересчитывается при смене статуса задачи.
- [ ] Каждое изменение попало в `audit_log`.

## ORB-014 — Задачи: модель и CRUD

- Оценка: L · Зависит от: ORB-053, ORB-010, ORB-011 · Блокирует: ORB-015..ORB-024, ORB-029, ORB-038
- Требования ТЗ: 6.2, 7 · Решения: ADR-0004

**Объём.** Таблица `tasks` из SPEC 1.4, генерация `code`, CRUD, фильтры (исполнитель,
куратор, проект, направление, приоритет, статус, срок), сортировки, вычисляемые
`is_overdue` и `days_overdue`, задача вне проекта, признак `is_control`.

**Критерии приёмки.**
- [ ] Задача создаётся как внутри проекта, так и вне его.
- [ ] `is_overdue` считается по ADR-0004; смена статуса на «Выполнена» снимает просрочку.
- [ ] Фильтр «просроченные» использует индекс `(status, due_at)` — подтверждено `EXPLAIN`.
- [ ] Исполнитель задачи — сотрудник агентства из справочника `people`, а не
      пользователь системы (ADR-0011): в ORBITA он не входит.
- [ ] Переходы статусов валидируются: из `done` нельзя вернуться в `new` минуя `in_progress`.

## ORB-017 — Вложения и версии

- Оценка: L · Зависит от: ORB-011, ORB-014 · Блокирует: ORB-033, ORB-043
- Требования ТЗ: 6.6 · Решения: ADR-0009 · Открытый вопрос: Q7

**Критерии приёмки.**
- [ ] Повторная загрузка файла с тем же именем создаёт версию, а не второй документ.
- [ ] Одинаковый по содержимому файл (совпадает sha256) не создаёт новую версию.
- [ ] Файл раздаётся presigned-ссылкой с ограниченным временем жизни, не через приложение.
- [ ] Превышение лимита размера и запрещённый тип отклоняются с понятным сообщением.
- [ ] Предпросмотр PDF и изображений работает; для DOCX и XLSX создаётся производный PDF.
