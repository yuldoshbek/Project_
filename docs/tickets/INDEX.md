## Что изменилось в приоритетах

Раньше очередь шла по этапам ТЗ: сначала ввод данных, потом видимость, потом контроль.
Теперь порядок другой, и вот почему.

1. **Презентационный слой поднят вперёд отчётности.** Дашборд, Гантт, «Сегодня» и новый
   экран «Доклад» (ORB-061) — это и есть продукт: если руководитель не понял картину за
   полминуты, остальное неважно.
2. **Бот и календарь поднялись из этапа 3 в основной объём.** Руководитель читает Telegram
   постоянно, а систему открывает раз в день. Канал, который не читают, задачу не решает.
3. **Мастер быстрого ввода (ORB-023) поднят.** Все данные вносит один человек вручную;
   стоимость ввода определяет, будет система жить или умрёт через месяц.
4. **Отчётность (ORB-043, ORB-044) опущена.** Она нужна раз в месяц, а сводка — каждый день.
5. **Снимки состояния (ORB-063) идут раньше динамики (ORB-064).** Вопрос руководителя —
   «где мы проседаем», а это про движение, а не про сегодняшний цвет
   ([ADR-0014](../adr/ADR-0014-progress-history.md)). Ретроспектива не
   восстанавливается: снимки должны копиться **до** первого показа дашборда, иначе
   первый месяц эксплуатации пройдёт без ответа на главный вопрос.

## Критический путь

```
003 → 004 → 006 → 007 → 053 → 011 → 014 → 029 → 061   (доклад руководителю)
                                     └→ 063 → 064          (динамика: где проседаем)
                                     └→ 036 → 054 → 055 (сводка в Telegram)
                                     └→ 057 → 058/059 → 060 (календарь)
```

Ветка «доклад» — главная: она закрывает основной сценарий. Ветки «бот» и «календарь»
подключаются к готовым агрегатам и друг от друга не зависят.

этом надо сказать заранее, иначе первое впечатление будет «не работает».

## Правила параллельной работы

1. **Миграции — точка конфликта номер один.** У Alembic линейная цепочка `down_revision`;
   две миграции, созданные параллельно, дадут расходящиеся головы. В пределах волны
   миграции создаёт один тикет. Перед слиянием `alembic heads` должен показывать одну голову.
2. **Файлы общего пользования** (`main.py`, корневой роутер, словари локализации,
   `Makefile`) правит только владелец волны.
3. **Один тикет — одна ветка.** Ветка `orb-014-tasks-crud`.
4. **Между тикетами `/clear`.**
5. **Тикет закрыт** после `/verify` и `/code-review`, не после написания кода.
