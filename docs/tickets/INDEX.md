## Правила параллельной работы

1. **Миграции — точка конфликта номер один.** У Alembic линейная цепочка `down_revision`;
   два агента, создавшие миграции параллельно, дадут расходящиеся головы. Правило: в
   пределах волны миграции создаёт **один** тикет; остальные, если нужна схема, ждут
   следующей волны либо описывают требуемые поля в своём тикете, а миграцию добавляет
   владелец. Перед слиянием — `alembic heads` должен показывать одну голову.
2. **Файлы общего пользования** (`main.py`, роутер верхнего уровня, `i18n` словари,
   `Makefile`) правит только тикет-владелец волны; остальные добавляют свои файлы, а
   подключение делают одной строкой в конце — конфликт на одну строку разрешается тривиально.
3. **Один тикет — одна ветка — один worktree.** Ветка `orb-014-tasks-crud`.
4. **Между тикетами `/clear`.** Контекст прошлого тикета мешает следующему.
5. **Тикет считается закрытым** только после `/verify` и `/code-review`; «код написан» —
   не признак готовности.
