# Эпик E4 — Нефункциональные требования и приёмка

Сквозные тикеты. Часть из них стартует параллельно с E1–E3, часть закрывает приёмку
(ТЗ 14). Сюда же вынесен явный список того, что в MVP не делается.

---

## ORB-047 — Резервное копирование и восстановление

- Оценка: M · Зависит от: ORB-002 · Требования ТЗ: 10.4, 14 · Открытый вопрос: Q9

**Объём.** Ежедневный `pg_dump` по расписанию, копия бакета вложений, согласованность
между ними (метка времени), хранение копий, скрипт восстановления, инструкция.

**Критерии приёмки.**
- [ ] Копия создаётся автоматически ежедневно, старые ротируются по заданному сроку.
- [ ] Проведён и задокументирован прогон восстановления на чистом окружении.
- [ ] Восстановление укладывается в один рабочий день (фактическое время зафиксировано).
- [ ] Восстановленная система согласована: ссылки на файлы из БД разрешаются.

## ORB-048 — Локализация: три письменности

- Оценка: M · Зависит от: ORB-005 · Требования ТЗ: 10.3 · Открытый вопрос: Q8

**Критерии приёмки.**
- [ ] Интерфейс полностью переведён на ru, uz-Cyrl, uz-Latn; непереведённых ключей нет (проверяется скриптом в CI).
- [ ] Форматы дат, чисел и множественных форм соответствуют локали.
- [ ] Данные, введённые на любой из трёх раскладок, сохраняются и отображаются без искажений.
- [ ] Добавление локали `en` (ТЗ 10.3) не требует изменений в коде компонентов.

---

## ORB-049 — Адаптивная вёрстка

- Оценка: M · Зависит от: ORB-018, ORB-020, ORB-030 · Требования ТЗ: 10.5

**Критерии приёмки.**
- [ ] От 1024 px — полная функциональность (ноутбук, планшет).
- [ ] От 360 px — просмотр задач и смена статуса, без горизонтальной прокрутки.
- [ ] Таблицы на узком экране превращаются в карточки, а не в прокручиваемую простыню.

---

## ORB-050 — Безопасность и подготовка к проверке СБ

- Оценка: L · Зависит от: ORB-008, ORB-017, ORB-033 · Требования ТЗ: 10.1, 14
- Решения: ADR-0003, ADR-0007

**Критерии приёмки.**
- [ ] TLS, HSTS, CSP, `X-Content-Type-Options`, безопасные атрибуты cookie.
- [ ] Ограничение частоты запросов на вход и на поиск.
- [ ] Режим `restricted` покрыт тестами во всех точках выдачи: списки, поиск, экспорт, уведомления, .ics.
- [ ] Зависимости проверены на известные уязвимости в CI, критических нет.
- [ ] Подготовлен пакет для СБ: модель угроз, матрица прав, описание журналирования и хранения.

## ORB-051 — Нагрузочная проверка

- Оценка: M · Зависит от: ORB-029, ORB-031 · Требования ТЗ: 10.2

**Критерии приёмки.**
- [ ] Сгенерирован набор: 200 проектов, 3000 задач, 20 000 комментариев.
- [ ] 60 одновременных сессий: p95 дашборда не более 400 мс, p95 списков не более 250 мс.
- [ ] Отчёт с профилем медленных запросов приложен; найденные N+1 устранены.

---

## ORB-052 — Приёмочный набор данных и прогон сценариев

- Оценка: M · Зависит от: E1, E2 · Требования ТЗ: 14, 8

**Критерии приёмки.**
- [ ] Загружен реальный набор: не менее 10 проектов и 50 задач агентства.
- [ ] Сценарии U1–U8 пройдены вручную, по каждому зафиксировано время и результат.
- [ ] U1 (создание проекта) и постановка задачи укладываются в норматив ТЗ 10.5.
- [ ] U7 (изоляция данных нового сотрудника) подтверждён вручную и автотестом.
- [ ] Протокол UAT подписан аппаратом заместителя директора.

## Явно вне MVP (этап 4 ТЗ, отдельный цикл планирования)

| Что | Почему отложено |
|---|---|
| ИИ-слой: резюме проекта, подсказки формулировок, автоклассификация поручений | ТЗ 11.3 прямо выносит за MVP; требует накопленных данных |
| Двусторонняя синхронизация с Google и Outlook | ТЗ 6.3 — «на последующих этапах»; в MVP только выгрузка |
| Документооборот с ЭЦП | ТЗ 2.5 — система не заменяет ведомственный СЭД |
| Бюджетный и бухгалтерский учёт | ТЗ 2.5 — только справочное поле «бюджет» |
| Мобильное приложение | ТЗ 10.5 требует адаптивную вёрстку, не приложение |
| Учёт трудозатрат | В ТЗ не заявлено, вопрос Q12 |
| Редактирование сроков перетаскиванием на диаграмме Ганта | Требование не заявлено, риск случайных правок |
