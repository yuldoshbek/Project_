# Эпик E3 — Контроль: уведомления, эскалация, отчётность, SETA

Этап 3 ТЗ. Результат — автоматизация рутинного контроля сроков; помощник перестаёт быть
«живым будильником» (ТЗ 2.4).

---

## ORB-036 — Инфраструктура фоновых задач

- Оценка: M · Зависит от: ORB-002, ORB-003 · Блокирует: ORB-037, ORB-042, ORB-044
- Решения: ADR-0008

**Объём.** ARQ-воркер, расписания (cron-задания), контекст выполнения с системным актором
для аудита, повторные попытки с экспоненциальной задержкой, «мёртвая очередь», метрики.

**Критерии приёмки.**
- [ ] Воркер поднимается в docker-compose и в CI.
- [ ] Падение задания не роняет воркер, ошибка попадает в лог с `request_id` задания.
- [ ] Повторный запуск любого регламентного задания на тех же данных не даёт побочных эффектов.

## ORB-037 — Уведомления: модель и центр в интерфейсе

- Оценка: L · Зависит от: ORB-036, ORB-007 · Блокирует: ORB-038, ORB-040, ORB-041
- Требования ТЗ: 6.5 · Решения: ADR-0008

**Объём.** `notifications` с уникальным `dedup_key`, `notification_preferences`, порт
`NotificationChannel`, реализация `in_app`, разделение планирования и отправки, тихие часы.

**Критерии приёмки.**
- [ ] Двойной прогон планировщика не создаёт вторую запись (уникальный индекс по `dedup_key`).
- [ ] Пользователь настраивает каналы по типам событий; настройки соблюдаются.
- [ ] Уведомление вне рабочего окна откладывается, кроме приоритета «Срочно».
- [ ] Непрочитанные видны счётчиком, отмечаются прочитанными, ведут к источнику.

## ORB-038 — Напоминания о приближающемся сроке

- Оценка: M · Зависит от: ORB-037, ORB-014 · Требования ТЗ: 6.5

**Критерии приёмки.**
- [ ] Напоминания за 1, 3 и 7 дней; интервалы настраиваются в справочнике.
- [ ] Перенос срока задачи отменяет старые запланированные напоминания и планирует новые.
- [ ] Выполненная или отменённая задача напоминаний не порождает.

## ORB-039 — Эскалация нарушенных сроков ✂️ сокращён

> **Сокращён 08.09.2026.** Эскалировать некому: цепочки «куратор → помощник →
> руководитель» не существует. Остаётся напоминание помощнику и пометка в утренней
> сводке руководителю (ORB-055). Уровни 1–3 и таблица `escalations` не нужны.

- Оценка: L · Зависит от: ORB-038 · Требования ТЗ: 6.5, сценарий U4 · Решения: ADR-0008
- Открытый вопрос: Q4

**Критерии приёмки.**
- [ ] Уровни 1–3 (куратор, помощник, руководитель) срабатывают по заданным интервалам.
- [ ] Приоритет «Срочно» стартует эскалацию сразу после срока, остальные — с задержкой.
- [ ] Смена статуса или продление срока останавливает эскалацию.
- [ ] Один и тот же уровень по одной задаче и одному сроку не срабатывает дважды.
- [ ] История эскалаций видна в карточке задачи.

## ORB-040 — Канал e-mail

- Оценка: M · Зависит от: ORB-037 · Требования ТЗ: 6.5, 12 · Открытый вопрос: Q13

**Критерии приёмки.**
- [ ] Письма уходят через настраиваемый SMTP, в dev — в MailHog.
- [ ] Шаблоны писем локализованы по локали получателя.
- [ ] Недоступность SMTP не теряет уведомление: запись остаётся неотправленной и повторяется.

## ORB-041 — Канал Telegram через адаптер SETA ⛔ снят

> **Снят 08.09.2026.** SETA ещё в разработке, API нет. Свой бот пишется в
> ORB-054…056 ([ADR-0013](../adr/ADR-0013-telegram-bot.md)). Порт `NotificationChannel`
> сохраняется — реализация SETA подключится, когда её API появится.

- Оценка: M · Зависит от: ORB-037 · Требования ТЗ: 6.5, 12, 3.4 · Решения: ADR-0001, ADR-0007
- Открытый вопрос: Q2

**Критерии приёмки.**
- [ ] Реализация `NotificationChannel` для Telegram включается настройкой, без правок ядра.
- [ ] Сообщение содержит ссылку, открывающую карточку в веб-версии или в Mini App.
- [ ] Для `restricted`-проектов уходит обезличенный текст без названия и содержания.
- [ ] Недоступность SETA не роняет отправку по другим каналам.

## ORB-042 — Повторяющиеся задачи

- Оценка: M · Зависит от: ORB-036, ORB-014 · Требования ТЗ: 6.2

**Критерии приёмки.**
- [ ] Правило повторения задаётся в формате RRULE (еженедельно, ежемесячно и т. п.).
- [ ] Экземпляры создаются реальными записями заранее (горизонт настраивается), с исполнителем и сроком.
- [ ] Изменение правила не трогает уже созданные и начатые экземпляры.
- [ ] Остановка повторения прекращает создание новых, не удаляя прошлые.

## ORB-043 — Отчёты: конструктор и экспорт в Word и Excel

- Оценка: L · Зависит от: ORB-011, ORB-014, ORB-017 · Требования ТЗ: 6.7, 12, сценарий U5
- Открытый вопрос: Q3 (без образцов бланков оценка недостоверна)

**Критерии приёмки.**
- [ ] Конструктор: выбор полей, периода и фильтров перед выгрузкой.
- [ ] Выгрузка в .docx и .xlsx открывается в MS Office без предупреждений о повреждении.
- [ ] Кириллица и узбекская латиница отображаются корректно, длинные названия не обрезаются.
- [ ] Строки `restricted`-проектов исключены, в конце отчёта — пометка об исключении (ADR-0007).
- [ ] Сохранённое определение отчёта переиспользуется.

## ORB-045 — Администрирование: пользователи, роли, аудит ✂️ сокращён

> **Сокращён 08.09.2026.** Двух пользователей не администрируют. Остаётся
> просмотр журнала изменений и выгрузка его в Excel — для отчётности, не для контроля
> доступа.

- Оценка: M · Зависит от: ORB-009, ORB-035 · Требования ТЗ: 6.8, 5

**Критерии приёмки.**
- [ ] Создание, деактивация пользователей и назначение глобальных ролей в интерфейсе.
- [ ] Журнал аудита фильтруется по актору, сущности, действию и периоду; выгружается в Excel.
- [ ] Администратор не получает доступ к содержимому чужих проектов (ADR-0003) — проверено тестом.

## ORB-046 — Провайдер личности SETA ⛔ снят

> **Снят 08.09.2026.** Ждать нечего: API SETA не существует, а пользователей
> двое и заводятся они сидами. Вернуть, когда у SETA появится API.

- Оценка: M · Зависит от: ORB-006 · Требования ТЗ: 3.4, 11.1 · Решения: ADR-0001
- Открытый вопрос: Q2 (тикет не начинается, пока нет ответа)

**Критерии приёмки.**
- [ ] Реализация `IdentityProvider` для SETA: сопоставление по `external_seta_id`, синхронизация профиля.
- [ ] Переключение провайдера — настройкой, без изменения роутеров и экранов.
- [ ] Пользователь, пришедший из SETA, получает роли по правилу сопоставления, а не вручную.
- [ ] Вход через Telegram Mini App работает с тем же набором прав, что и веб-вход.
