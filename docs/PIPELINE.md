# Процесс разработки ORBITA

Пайплайн реализован проектными командами (`.claude/commands`) и скиллами
(`.claude/skills`) — работает без внешних плагинов.

```
/council                        делать ли это вообще, вариант A или B
    │                           → docs/council/, docs/adr/
    ▼
/grill <раздел>                 допрос требования до конца
    │                           → docs/CONTEXT.md, docs/adr/, docs/OPEN-QUESTIONS.md
    ▼
/to-spec → /to-tickets          спецификация и тикеты с зависимостями
    │                           → docs/PLAN.md, docs/tickets/
    ▼
using-git-worktrees             дерево на тикет
+ dispatching-parallel-agents   раздать волну тикетов агентам
    ▼
/tdd ORB-NNN → /implement       по одному тикету за заход, /clear между тикетами
    ▼
/verify                         проверка фактами, а не ощущением
+ /code-review                  встроенная команда Claude Code
    ▼
/finish-branch                  слияние, уборка дерева, обновление документов
```

## Правила, которые нельзя нарушать в процессе

- **Один тикет — одна ветка — одно рабочее дерево.**
- **`/clear` между тикетами.** Контекст прошлого тикета мешает следующему.
- **Готовность — это `/verify`,** а не «код написан».
- **В одной волне миграции создаёт один тикет.** Иначе расходятся головы Alembic.
- **Ни одного ключа и ни одного настоящего документа агентства в репозитории.** Он
  публичный: сервисный токен SETA — только в окружении и GitHub Secrets, файлы `*.docx` —
  в `.gitignore`.
- **Неотвеченный вопрос не угадывается:** реализуем по допущению из OPEN-QUESTIONS и
  называем это вслух.
