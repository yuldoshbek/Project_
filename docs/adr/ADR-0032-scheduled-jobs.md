# ADR-0032. Фоновые задачи по расписанию вместо постоянного воркера

- Статус: принято · Дата: 20.09.2026 · Контекст: [ADR-0028](ADR-0028-hosting.md) — API
  живёт функциями в облаке, где постоянного процесса нет
- **Отменяет** Redis и воркер ARQ из прежнего стека
- Связано: инвариант «фоновые задачи идемпотентны»

## Контекст

Прежде фон держался на связке Redis + ARQ: постоянный процесс, очередь, повторы с
задержкой. В облаке функций постоянного процесса нет, а держать Redis и воркер ради двух
пользователей и пяти задач в сутки — это отдельная инфраструктура, которую придётся
сопровождать.

Задачи системы редкие и по расписанию: утренняя сводка в 08:30, ежедневные снимки
состояния, проверка сроков, напоминания, ночной сброс демо‑данных.

## Решение

- Порт **`Scheduler`**: задача — это именованный обработчик, который можно вызвать в любой
  момент и сколько угодно раз.
- В облаке задачи запускает расписание платформы, обращаясь к защищённому эндпоинту
  `/internal/jobs/{name}` с секретом в заголовке. На сервере агентства тот же обработчик
  вызывает cron в контейнере.
- **Идемпотентность обязательна.** Факт выполнения за период фиксируется в базе: повторный
  вызов в тот же день не шлёт второго уведомления и не собирает второго отчёта.
- Доставка «по возможности»: расписание платформы может пропустить запуск или вызвать
  дважды. Поэтому у каждой задачи есть догоняющий режим — она сама видит, что за вчера
  снимок не сделан, и делает его.
- Долгих задач нет: тяжёлый разбор таблицы Ижро идёт в обработчике загрузки по частям, а
  не в фоне.

## Отвергнутые варианты

- **Держать Redis и воркер в облаке.** Отдельный платный сервис и постоянный процесс ради
  пяти задач в сутки.
- **Очереди платформы.** Пока в бете; класть на них утреннюю сводку рано.

## Последствия

- Из `docker-compose` уходят Redis и воркер; локально задачи вызываются той же командой.
- Уведомление, которое обязано прийти точно в 08:30, может опоздать на несколько минут —
  это приемлемо и записано в ТЗ.
- Тест на идемпотентность — обязательный критерий приёмки каждой задачи.
