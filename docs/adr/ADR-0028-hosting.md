# ADR-0028. Размещение: облако сейчас, сервер агентства потом; код одинаковый

- Статус: принято · Дата: 20.09.2026 · Контекст: решение заказчика 19–20.09.2026 —
  «фронт на Netlify, бэкенд на Vercel, база PostgreSQL, GitHub — центр»; свой сервер
  готовится под бота SETA
- **Отменяет** требование ТЗ v1.0 10.1 о размещении только внутри республики и часть
  [ADR-0026](ADR-0026-no-login-perimeter-auth.md) про сервер агентства
- Связано: [ADR-0029](ADR-0029-access-by-link.md), [ADR-0032](ADR-0032-scheduled-jobs.md)

## Контекст

Заказчик хочет видеть каждое изменение сразу и не хочет ждать своего сервера. Он же
сообщил, что сервер готовится и ORBITA переедет на него позже.

Закон о персональных данных с 27.03.2026 разрешает хранить данные граждан за рубежом в
странах утверждённого перечня, куда входит Германия. Старое требование ТЗ 10.1 заказчик
снял вместе со старым ТЗ. Решение о размещении реальных данных принял он сам, устно и
письменно, риск ему назван.

## Решение

**Два контура из одного репозитория и одного конвейера.**

| | Облако (сейчас — рабочий контур) | Сервер агентства (позже) |
|---|---|---|
| Интерфейс | Netlify, проксирует `/api` на Vercel | тот же сервер, что и API |
| API | Vercel Functions, FastAPI, регион Франкфурт | Docker, uvicorn |
| База | PostgreSQL (Neon), Франкфурт | PostgreSQL в Docker |
| Файлы | Vercel Blob, закрытый режим | S3‑совместимое хранилище |
| Расписание | задачи по расписанию Vercel | cron в контейнере |

**Превью каждого PR** поднимается в облаке на **ветке демо‑базы с вымышленными данными**.
Ветка рабочей базы для превью не используется никогда.

**Переносимость — обязательное свойство, а не обещание.** Внешний мир спрятан за портами
`FileStorage`, `Scheduler`, `PushSender`. Ничего специфичного для Vercel в сервисах и
домене нет. Переезд описан в `docs/RUNBOOK.md` и проверяется в блоке 3 сборкой на чистой
машине.

## Отвергнутые варианты

**Всё сразу на сервере агентства.** Сервера ещё нет, а превью на каждое изменение — то,
ради чего заказчик и просил GitHub как центр.

**Держать фронт и API на одной платформе.** Технически проще: не было бы прокси и таймаута
в 26 секунд. Но Netlify у заказчика уже есть, и он назвал его прямо.

## Последствия

- Прокси Netlify даёт один источник для браузера, поэтому cookie сессии — первого лица, а
  CORS не нужен вовсе.
- Таймаут прокси в 26 секунд закрывает постоянное соединение: обновление идёт опросом
  ([ADR-0034](ADR-0034-near-real-time.md)).
- Тело запроса к функции ограничено 4,5 МБ, поэтому файлы загружаются в хранилище по
  подписанной ссылке, а не через API.
- Стоимость облака — примерно $20–40 в месяц.
- Реальные данные лежат в чужом облаке. Это осознанное решение заказчика; при переезде на
  свой сервер оно отменяется само.
