# ADR-0006. Поиск на русском, узбекской кириллице и узбекской латинице

- Статус: принято · Дата: 08.09.2026 · Контекст: ТЗ 6.9, 10.3

## Контекст

ТЗ требует глобальный поиск с учётом трёх систем письма. Практическая проблема: один и тот
же партнёр может быть записан как «Ўзбекистон», «Oʻzbekiston», «Узбекистан» — и все три
написания должны находиться по любому из запросов. Стандартный `to_tsvector('russian')`
этого не даёт: узбекская латиница для него — набор латинских слов, а кириллические ў, қ,
ғ, ҳ не сводятся к своим латинским парам.

Дополнительная сложность: пользователи набирают `o'zbekiston`, `oʻzbekiston` и
`ozbekiston` — с прямым апострофом, с модификатором и без него.

## Решение

Поиск строится на нормализованном представлении, а не на исходном тексте:

1. Функция `orbita.normalize_search(text)` (IMMUTABLE, на SQL):
   - приводит к нижнему регистру;
   - транслитерирует узбекскую латиницу в кириллицу по таблице соответствий
     (`oʻ→ў`, `gʻ→ғ`, `sh→ш`, `ch→ч`, `ng→нг`, `q→қ`, `h→ҳ`, `x→х` и т. д.);
   - убирает апострофы всех начертаний и диакритику (`unaccent`);
   - схлопывает пробелы.
2. У проектов и задач — генерируемый столбец `search_vector tsvector`, построенный из
   `normalize_search(title || description || ...)` с конфигурацией `simple`
   (морфология русского здесь только мешает: узбекские слова она искажает).
3. GIN-индекс по `search_vector` — точные совпадения слов.
4. GIN-индекс `gin_trgm_ops` по `normalize_search(title)` — опечатки и частичный ввод.
5. Ранжирование: совпадение в названии выше, чем в описании, выше, чем в комментарии.
6. Содержимое вложений индексируется отдельным фоновым заданием (ORB-033), извлечение
   текста из PDF и DOCX синхронно в запросе делать нельзя.

## Последствия

Транслитерация односторонняя и приблизительная: она нужна для сопоставления, а не для
отображения — исходный текст всегда хранится как введён. Таблица соответствий покрывается
табличным тестом на реальных названиях организаций из справочника.

Порядок сортировки в интерфейсе для узбекской латиницы отличается от порядка в БД;
сортировка списков выполняется на стороне PostgreSQL с явным `COLLATE`, вопрос конкретной
локали вынесен в OPEN-QUESTIONS (Q8).
