# ADR-0036. Уведомления — Web Push из PWA по записи в `notifications`

- Статус: принято · Дата: 30.09.2026 · Контекст: ТЗ 8, V24, V26–V29
- **Заменяет** [ADR-0008](ADR-0008-notifications-escalation.md)
- Связано: [ADR-0028](ADR-0028-hosting.md), [ADR-0030](ADR-0030-frontend-stack.md),
  [ADR-0035](ADR-0035-scheduler-on-github-actions.md)

## Контекст

ADR-0008 писался под другой продукт: напоминания за 1, 3 и 7 дней, эскалация в три уровня,
каналы «внутри системы», e-mail и Telegram, воркер ARQ раз в пять минут. Из этого ТЗ v2.0
оставило одно — идемпотентность. Уведомлений два: утренняя сводка и пуш «ждёт вашего решения»
(ТЗ 8). Канал один — уведомления PWA, на iPhone после установки на экран «Домой». Воркера и
Redis нет (CLAUDE.md), расписание держит GitHub Actions (ADR-0035).

## Решение

**Канал — Web Push** (RFC 8030, шифрование RFC 8291, VAPID RFC 8292). Это стандарт, который
понимают Safari на iPhone (16.4+), Chrome и Firefox. Посредник не нужен: сервер сам шлёт
зашифрованное сообщение в службу доставки браузера (Apple, Google, Mozilla, Microsoft).

**Уведомление — запись, отправка — отдельный шаг.** Это из ADR-0008 остаётся. Запись в
`notifications` с детерминированным ключом повтора (`morning-summary:{день}:{пользователь}`,
`question:{вопрос}`) делается в той же транзакции, что и событие; отметка `sent_at` ставится,
когда сообщение принято хотя бы одной службой доставки. Повторный прогон упирается в ключ и
второго сообщения не шлёт (инвариант 10). Запасная защита на устройстве — `tag` уведомления:
то же сообщение, доставленное дважды, заменяет первое, а не встаёт вторым.

**Порт `PushSender`** (`app/adapters/push.py`): `WebPushSender` — когда задан ключ, иначе
`DisabledPushSender`, и экран честно говорит «уведомления не настроены». Ключ один — закрытый
ключ VAPID `ORBITA_VAPID_PRIVATE_KEY`; открытый выводится из него и отдаётся интерфейсу в
ответе сводки. Ключ вводит заказчик (SETUP), команда генерации — `python -m app.push_keys`.

**Текст уведомления собирает service worker**, а не сервер. Сервер шлёт данные — числа и
названия (`lock_screen`), тот же набор, что показывает превью на вкладке «Сводка», — а слова
берутся из ключей перевода интерфейса теми же функциями. Превью и настоящее уведомление
совпадают по построению, а формулировки живут в одном месте.

**Когда уходит.**

- Сводка — задача `morning-summary`: расписание зовёт её каждые 10 минут с 06:00 до 11:50.
  День занимает только доставленная сводка. До порога `summary_at`, без подписки и без ключа
  задача отвечает «ещё не время» с причиной и ничего не записывает о прогоне (V24); служба
  доставки не приняла ни одного сообщения — прогон записан неудачным, день свободен. Порог
  принимается с 06:00 до 11:00, чтобы после него оставалось шесть вызовов расписания (50
  минут, до 11:50).
- Пуш о вопросе — сразу после фиксации транзакции вопроса, в том же запросе (V27). Отдельного
  воркера для повторов нет: вопрос, который всё ещё ждёт, придёт в утренней сводке.

**Кому.** Руководителю (V28): подписку оформляет только он, на своём устройстве. Перевыпуск
ссылки удаляет подписки вместе с сессиями. Подписка, от которой служба доставки отказалась
навсегда (404/410), не удаляется, а помечается `gone_at`: иначе браузер, который всё ещё
помнит её, записал бы её снова при следующем открытии вкладки, и сводка терялась бы каждое
утро. Такой адрес сервер не принимает (410), и интерфейс оформляет новую подписку.

## Отвергнутые варианты

**pywebpush.** Тянет aiohttp и requests — двадцать пакетов ради одной функции, а каждая
зависимость — время холодного старта на Vercel. Взяты `http-ece` и `py-vapid` поверх `httpx`.

**Текст уведомления на сервере.** Второе место для формулировок, которые уже утверждены на
экране, и второе место для названий видов решения. Разошлись бы при первой правке.

**Пуш о вопросе через задачу по расписанию.** Даёт окно на «Отменить», но задержку до
интервала расписания, а ТЗ говорит «появилось».

**Эскалация, напоминания за N дней, тихие часы, e-mail, Telegram** (ADR-0008) — сняты ТЗ v2.0.

## Последствия

- «Отменить» вопрос удаляет и его неотправленное уведомление, но уже пришедший пуш не
  отзывается: касание откроет сводку, где вопроса нет (V27).
- Сообщение уходит до фиксации прогона задачи. Если фиксация сорвётся, следующий прогон
  отправит снова — устройство заменит уведомление тем же `tag`.
- Превью шлёт настоящие пуши только при заданном `PREVIEW_VAPID_PRIVATE_KEY`; без него
  уведомления там выключены (V30).
- На iPhone ORBITA на экране «Домой» хранит данные отдельно от Safari: сессию личной ссылки
  нужно проверить на живом телефоне (HANDOFF).
