# ADR-0007. Режим проектов ограниченного доступа

- Статус: принято · Дата: 08.09.2026 · Контекст: ТЗ 10.1, 15 (первый риск)

## Контекст

ТЗ прямо предупреждает: часть проектов по космическому мониторингу может относиться к
сведениям ограниченного доступа, и до переноса таких проектов в систему требуется
заключение службы безопасности. Заключение будет получено после начала разработки.

Соблазн — «сделаем обычные проекты, режим добавим потом». Это ошибка: ограничение доступа
затрагивает не карточку проекта, а поиск, экспорт, уведомления и журнал аудита. Добавление
режима позже означает переработку пяти подсистем и повторную проверку СБ.

## Решение

Поле `projects.classification` вводится в первой миграции, значения `internal` (по
умолчанию) и `restricted`. Для `restricted` действуют жёсткие правила:

- проект и его задачи видны **только** явным участникам `project_members`;
  роли `leader`, `assistant`, `admin` автоматического доступа не получают;
- содержимое не попадает в глобальный поиск для непричастных (фильтр применяется до
  ранжирования, а не после — иначе счётчик результатов выдаёт факт существования проекта);
- уведомления по таким задачам уходят только внутрь системы и по e-mail; в Telegram
  отправляется обезличенное «есть обновление по проекту», без названия и текста;
- экспорт в Word и Excel: строки исключаются, а в конце отчёта печатается пометка
  «часть записей исключена по уровню доступа» — молча терять данные в отчёте нельзя;
- смена `classification` — отдельное право, событие пишется в `audit_log` с повышенной
  категорией, о смене уведомляется администратор.

## Последствия

Каждая новая точка выдачи данных наружу (поиск, экспорт, канал уведомлений, будущий
ИИ-слой) обязана явно объявить, как она обращается с `restricted`. Это фиксируется
чек-листом в `/verify`. Стоимость — одно дополнительное условие в запросах и один
дополнительный тест на каждую точку выдачи.

Заключение СБ может ужесточить требования (например, потребовать отдельное хранилище
файлов для таких проектов). Это учтено: `FileStorage` — порт, а не прямые вызовы S3.
