# ADR-0031. Сервисный слой: единица работы и один сервис показателей

- Статус: принято · Дата: 20.09.2026 · Контекст: аудит 19.09.2026 — слой `repos` существует
  только на бумаге, транзакция теряет изменения при досрочном выходе, тесты подменяют
  боевую транзакцию, шаблон CRUD повторён в четырёх сервисах
- Уточняет [ADR-0001](ADR-0001-architecture-variant.md)
- Связано: [ADR-0010](ADR-0010-audit-log.md), [ADR-0004](ADR-0004-overdue-is-computed.md)

## Контекст

В прежнем коде SQL жил в сервисах, роутере, воркере и адаптерах, а в `repos` не было ни
одного запроса. Граница транзакции переехала внутрь фичи без решения. Примитив с `commit`
после `yield` терял изменения при досрочном выходе — из-за этого пароль однажды не
сохранялся, а тесты этого не видели, потому что подменяли сессию.

При этом требование «одни и те же цифры во всех местах» — не пожелание: экран, отчёт,
уведомление и сценарий «что если» обязаны считать одинаково.

## Решение

1. **Единица работы (Unit of Work).** Сценарий открывает одну транзакцию, внутри — только
   работа с данными. Внешние действия (отправка уведомления, запись файла) выполняются
   **после** фиксации, через исходящую очередь в базе.
2. **Запросы живут в `repos`.** В сервисах SQL нет. Чтение для экранов — отдельные
   read‑модели: один запрос на экран, а не N запросов на карточку.
3. **Один сервис показателей.** Сигналы, лестница внимания, признак жизни, скорость
   ответа, «успеваем?» считаются в одном месте и одними функциями. API, отчёты,
   уведомления и «что если» вызывают его.
4. **«Что если» не пишет ничего.** Тот же код с теми же правилами, но в режиме расчёта;
   запись происходит только по отдельному действию «применить».
5. **Журнал изменений** пишется примесью в той же транзакции, что и изменение.
6. **Тесты не подменяют транзакцию.** Проверяется настоящая фиксация и откат на настоящей
   PostgreSQL; повторяющийся шаблон CRUD покрывается общими тестами, а не копиями.

## Отвергнутые варианты

- **Оставить как есть.** Слой, существующий только в документации, хуже его отсутствия:
  правило нарушается молча.
- **Убрать `repos` совсем и писать SQL в сервисах.** Честнее прежнего, но тогда read‑модели
  и запись перемешиваются, и «один запрос на экран» не удержать.

## Последствия

- Сервисы и роутеры прежнего кода (около 3 тыс. строк) переписываются.
- Появляется исходящая очередь: уведомление не уходит, если транзакция откатилась.
- Проверка «цифры совпадают» становится тестом, а не договорённостью.
