# ADR-0029. Доступ по личной ссылке вместо входа

- Статус: принято · Дата: 20.09.2026 · Контекст: решение заказчика 20.09.2026 — «не нужно
  ничего, бесперебойный вход по ссылке»
- **Заменяет** [ADR-0026](ADR-0026-no-login-perimeter-auth.md): периметра больше нет,
  система стоит в открытом интернете
- Связано: [ADR-0028](ADR-0028-hosting.md), [ADR-0011](ADR-0011-two-user-scope.md)

## Контекст

Пароли заказчик отверг дважды. При этом система переехала в публичное облако, где нет
периметра, а руководитель открывает её с iPhone из любой сети. Без всякой проверки любой,
кто узнал адрес, читал бы и менял поручения Администрации Президента.

## Решение

**У каждого из двух пользователей своя секретная ссылка.**

- Ссылка содержит случайный токен не меньше 32 байт. В базе хранится только его отпечаток.
- Переход по ссылке ставит cookie сессии: `__Host-`, `Secure`, `HttpOnly`, `SameSite=Lax`,
  срок 30 дней с продлением при каждом входе. Дальше пользователь просто открывает
  приложение.
- Ссылка перевыпускается одной кнопкой в разделе «Управление»; старая сразу перестаёт
  работать.
- Видно, когда ссылка выпущена и когда по ней заходили последний раз.
- Проверка стоит **в одном месте** — на входе в API. Роль (помощник или руководитель)
  подписывает действие в журнале, но ничего не прячет: оба видят всё.
- Поисковые роботы отключены заголовком; ссылка нигде не печатается в логи.

## Отвергнутые варианты

**Пароли.** Отвергнуты заказчиком, и для двоих знакомых людей они действительно только
мешают.

**Passkeys (Face ID).** Технически лучший вариант: ключ не украсть пересылкой ссылки. Но
это снова «вход», от которого заказчик отказался дважды. Оставлено как запасной путь: если
ссылка утечёт, переход на passkeys — это одна неделя работы.

**Открытый адрес без проверки.** Означает публикацию поручений АП в интернете.

## Последствия

- Кто переслал ссылку, тот отдал доступ. Поэтому перевыпуск сделан мгновенным, а в
  «Управлении» видно время последнего входа — чужой вход заметен.
- Токены — это секрет: они не попадают ни в репозиторий, ни в журналы сборки, ни в
  отчёты об ошибках.
- Дополнительный слой: API принимает запросы только через прокси Netlify, прямое обращение
  к адресу функции отклоняется.
