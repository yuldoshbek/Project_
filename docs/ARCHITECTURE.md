## 1. Общая картина

```
           iPhone руководителя            ноутбук помощника          большой монитор
                    │                             │                        │
                    └──────────── одно веб-приложение (PWA) ────────────────┘
                                          │
                              Netlify: раздаёт интерфейс,
                              проксирует /api первым лицом
                                          │
   GitHub Actions ──────────▶ Vercel: FastAPI, регион Франкфурт
   расписание задач,                      │
   выкладка, копия базы       ┌───────────┴───────────┐
                              │                       │
                      PostgreSQL (Neon)       S3‑совместимое хранилище
                      рабочая / демо          файлы — ждёт решения V44
```

Сборка для сервера агентства уже есть — `deploy/server`: Caddy раздаёт интерфейс и API с
одного адреса, рядом PostgreSQL, cron и файлы на диске сервера (том `uploads`). Порядок
переезда — [RUNBOOK](RUNBOOK.md). Приложение об этом не знает — различия спрятаны за
портами и настройками.

## 2. Backend

`backend/app`, слоями сверху вниз; обратные импорты запрещены и проверяются import-linter
(`backend/pyproject.toml`).

| Слой | Что внутри | Чего там нет |
|---|---|---|
| `api/` | роутеры, схемы запросов и ответов, проверка сессии, граница транзакции | бизнес-логики |
| `jobs/` | реестр задач с правилом «период — один раз» (`registry.py`), обработчики | расчётов: обработчик только зовёт сценарии |
| `services/` | сценарии, журнал изменений, **сервис показателей** | FastAPI и HTTP |
| `adapters/` | `FileStorage`, `PushSender`, `SetaGateway`, разбор docx | знаний о сценариях |
| `repos/` | модели и запросы, read‑модели для экранов | правил предметной области |
| `domain/` | правила, инварианты, вычисления над значениями | FastAPI и SQLAlchemy — запрет проверяется линтером |

Запросы для экранов собраны в read‑модели `repos/`. Правило «SQL только в `repos/`» линтер
не проверяет, и соблюдается оно не везде: часть сценариев `services/`, реестр задач
`jobs/registry.py` и `api/routes/access.py` делают точечные запросы сами.

**Сервис показателей** (`services/metrics.py`) — единственное место, где считаются сигналы,
лестница внимания, признак жизни, скорость ответа, отклонения и прогноз. Его вызывают
сценарии разделов, отчёты, задачи по расписанию и сценарий «что если». Два источника
расчёта разошлись бы в цифрах, и доверия не было бы ни к одному.

**Граница транзакции — запрос.** Изменения запроса и запись в журнал фиксируются одной
транзакцией, и фиксирует её класс маршрута (`api/transaction.py`, `CommitOnSuccess`) до
того, как ответ уйдёт клиенту. Действия наружу идут после фиксации, в том же запросе и
своей транзакцией (`after_commit`): так уходит пуш «ждёт вашего решения». Исходящей
очереди, которую задумывал ADR-0031, в коде нет: повод уведомления записывается в
`notifications` вместе с событием, а пуш о вопросе уходит один раз, без воркера и повторов —
[ADR-0036](adr/ADR-0036-web-push.md).

**«Что если»** — тот же код расчёта в режиме без записи (`metrics.what_if`). В базу не
попадает ничего, пока помощник не применит новые сроки отдельным действием.

**Порты** выбираются настройкой, а не правкой кода:

| Порт | Где | Реализации |
|---|---|---|
| `FileStorage` | `adapters/storage` | диск, S3, «не настроено» — раздел 5 |
| `PushSender` | `adapters/push.py` | Web Push или выключенный, если нет ключа — раздел 6 |
| `SetaGateway` | `adapters/seta.py` | одна: `NoSeta`, SETA не подключена |
| `Scheduler` | `jobs/` и `/internal/jobs/{name}` | не класс, а именованные задачи за защищённым адресом — раздел 7 |

Порта `ReportRenderer` в коде нет: отчёт недели и месяца и справка по Ижро печатаются в PDF
браузером (`sections/pult/Report.tsx`, `sections/ijro/Spravka.tsx`).

## 3. Frontend

`frontend/src`:

```
app/        маршруты, оболочка, тема, определение устройства, сессия, уведомления
shared/     клиент API, набор компонентов, i18n, время
sections/   по каталогу на раздел ТЗ, плюс «Захват» и режим «Совещание»
styles/     токены цвета (tokens.css) и проверка контраста
sw.ts       service worker PWA: оболочка без сети и пуши
```

- **Устройство определяет набор функций**, а не только сетку: телефон — решить, увидеть,
  записать; ноутбук — вносить и планировать; монитор — обзор и режим «Совещание».
- **Токены** — единственный источник цвета; тем две, обе проверяются на контраст счётом.
- **Компоненты** — свои, в манере shadcn/ui (`class-variance-authority`, Radix Slot), в
  `shared/ui`.
- **Данные** идут через TanStack Query (`shared/api/queries.ts`): опрос раз в 15 секунд,
  немедленное обновление при возврате на вкладку, остановка при скрытой вкладке.
- **Типы ответов API описаны руками** в `shared/api/orbita.ts` по схемам pydantic.
  Автоматической сверки с OpenAPI нет, поэтому поле ответа и его тип меняются одним
  изменением.

## 4. Данные

- PostgreSQL 16, схема `orbita`. Схема меняется только миграцией Alembic.
- У каждой редактируемой записи есть версия: одновременная правка двумя людьми даёт
  честный ответ «запись изменил помощник», а не молчаливую перезапись.
- Журнал изменений неизменяем и защищён триггерами.
- Происхождение данных видно на данных: сырое написание ФИО хранится рядом с
  сопоставленным сотрудником, у срока записано, откуда взялся год.
- **Ветки базы**: рабочая — с реальными данными; демо — с вымышленными. Превью каждого PR
  получает копию **демо**. Реальные данные в превью не попадают никогда.

## 5. Файлы

Порт `FileStorage`, реализация выбирается настройкой `ORBITA_STORAGE`, а когда она пуста —
по ключам S3 и окружению (`Settings.storage_kind`):

- **S3** — любое S3‑совместимое хранилище: браузер грузит и скачивает файл сам по
  подписанной ссылке, мимо API, — тело запроса к функции Vercel ограничено 4,5 МБ, и
  большие презентации через API не проходят;
- **диск** — разработка, тесты и сервер агентства (том `uploads`); файл идёт через API;
- **не настроено** — в облаке, пока не заданы ключи S3: загрузка честно отказывает
  «Хранилище файлов не настроено», остальное работает.

Где лежат файлы в облаке — открытый вопрос V44 ([OPEN-QUESTIONS](OPEN-QUESTIONS.md));
ключи хранилища вводит заказчик ([SETUP](SETUP.md)).

Исключение одно — **таблица «Ижро»**: её содержимое разбирает сервер, поэтому файл (сотни
килобайт) идёт телом запроса `POST /api/v1/ijro/imports` и читается адаптером
`adapters/docx.py` на stdlib — без `python-docx` и без `multipart`. Сам файл в хранилище не
кладётся: у партии привоза остаются имя, sha256 и построчный отчёт.

## 6. Уведомления

Порт `PushSender` (`adapters/push.py`, [ADR-0036](adr/ADR-0036-web-push.md)) — Web Push из
PWA: сервер шифрует сообщение и отдаёт его службе доставки браузера, ключ VAPID один на
контур. Нет ключа — порт выключен, и экран говорит, что уведомления не настроены. Пуш о
вопросе уходит после фиксации транзакции (раздел 2), текст уведомления собирает service
worker из ключей перевода интерфейса.

## 7. Задачи по расписанию

Порт `Scheduler` ([ADR-0032](adr/ADR-0032-scheduled-jobs.md)) в коде — не класс, а реестр
именованных задач (`jobs/registry.py`, `jobs/handlers.py`) за защищённым адресом
`/internal/jobs/{name}` с секретом в заголовке. Будильник — снаружи: в облаке
`.github/workflows/jobs.yml` ([ADR-0035](adr/ADR-0035-scheduler-on-github-actions.md)), на
сервере — контейнер `cron` (`deploy/server/crontab`). Вручную та же задача запускается из
командной строки, мимо адреса: `make job n=<имя>`.

Все задачи идемпотентны: лишний вызов не повторяет сделанного, неудачный не занимает
период. Сейчас это: утренняя сводка (расписание зовёт каждые 10 минут с 06:00 до 11:50,
задача отправляет с порога «Утренняя сводка», по умолчанию 08:30, и день занимает только
доставленная сводка), ежедневный снимок состояния и проверка сроков. Пропущенный вызов
сводки догоняет следующий, до 11:50; пропущенный снимок дня не восполняется — строки за
этот день в `job_runs` нет (`jobs/handlers.py`).

## 8. Доступ

Личная секретная ссылка `/api/access/<токен>` ставит cookie сессии на 30 дней. Проверка
одна, на входе в API (`api/security.py`, зависимость всего роутера данных). Роль
подписывает действие в журнале и ничего не прячет: оба пользователя видят всё.

Браузер ходит в API только через прокси Netlify: правило `/api/*` пишет при сборке
`frontend/scripts/write-redirects.mjs`. Источник для браузера один, cookie сессии — первого
лица, CORS не настроен. Сам адрес функции Vercel открыт — по нему расписание зовёт
`/internal/jobs/{name}`, а запрос без cookie сессии данных не получает. Отдельной проверки
«запрос пришёл через прокси», о которой говорит ADR-0029, в коде нет. На сервере агентства
`/internal` снаружи закрыт Caddy.

## 9. Окружения и конвейер

| Окружение | Когда обновляется | Данные |
|---|---|---|
| превью PR | на каждый push в ветку открытого PR | копия демо‑базы |
| рабочее | после слияния в `main`, по кнопке | реальные |

Работы конвейера (`.github/workflows`):

| Файл | Когда | Что делает |
|---|---|---|
| `ci.yml` | push в `main` и `block-*`, каждый PR | документы, backend, миграции, frontend, сценарии и снимки — пять независимых проверок |
| `preview.yml` | PR открыт и обновлён | ветка демо‑базы, API, интерфейс, ссылка в комментарии; при закрытии — уборка |
| `deploy.yml` | по кнопке | миграции, справочники, первая ссылка, выкладка, проверка коммита, откат площадок при неудаче |
| `jobs.yml` | по расписанию и вручную | вызов обработчиков задач |
| `backup.yml` | каждую ночь и вручную | снимок рабочей базы, проверка читаемости, уборка старых |

Что проверяется: ruff, mypy, import-linter, pytest на настоящей PostgreSQL, eslint,
stylelint, prettier, tsc, vitest, сборка с бюджетом размера, миграции (одна голова, схема
совпадает с моделями, откат и повторное применение), список зависимостей для функций не
отстал от блокировки. Playwright — пятая работа «Сценарии и снимки»: собранный интерфейс и
настоящий API на свежей базе с вымышленными данными; снимки трёх устройств в двух темах
выгружаются артефактом прогона. Обязательными для слияния в `main` все пять работ делают
правила ветки ([SETUP](SETUP.md), шаг 3).

Локально `make e2e` поднимает свой стенд: API на `:8001` с базой `orbita_e2e`, которую
`backend/app/e2e_stand.py` пересоздаёт перед каждым прогоном, и собранный интерфейс на
`:5174` (`frontend/e2e/stand.ts`). Окно `make dev` на 8000 и 5173 прогон не трогает; почему
стенд отдельный — в заголовке `e2e_stand.py`.

Откат: предыдущая выкладка одним действием; миграции пишутся по схеме «расширить →
переключить → сжать», чтобы откат кода не требовал отката схемы. Порядок — в
[RUNBOOK](RUNBOOK.md).

## 10. Границы

Чего в системе нет и не планируется без отдельного решения: постоянного воркера и Redis,
антивируса и преобразователя документов, внешних моделей ИИ, собственного бота, входа по
паролю, разграничения доступа между пользователями, обмена с SETA (порт есть, подключения
нет).
