## 1. Общая картина

```
           iPhone руководителя            ноутбук помощника          большой монитор
                    │                             │                        │
                    └──────────── одно веб-приложение (PWA) ────────────────┘
                                          │
                              Netlify: раздаёт интерфейс,
                              проксирует /api первым лицом
                                          │
                              Vercel: FastAPI, регион Франкфурт
                    ┌─────────────────────┼─────────────────────┐
                    │                     │                     │
            PostgreSQL (Neon)       Vercel Blob            расписание задач
            рабочая / демо           файлы                 сводка, снимки
```

Позже тот же код переезжает на сервер агентства: Caddy раздаёт интерфейс и API с одного
адреса, рядом PostgreSQL, S3‑совместимое хранилище и cron. Приложение об этом не знает —
различия спрятаны за портами.

## 2. Backend

`backend/app`, слоями сверху вниз; обратные импорты запрещены и проверяются линтером.

| Слой | Что внутри | Чего там нет |
|---|---|---|
| `api/` | роутеры, схемы запросов и ответов, проверка ссылки доступа | бизнес-логики и SQL |
| `jobs/` | обработчики задач по расписанию | собственной логики: только вызов сценариев |
| `services/` | сценарии, единица работы, транзакции, **сервис показателей** | SQL |
| `adapters/` | `FileStorage`, `PushSender`, разбор docx, экспорт, позже `SetaGateway` | знаний о сценариях |
| `repos/` | модели и запросы, read‑модели для экранов | правил предметной области |
| `domain/` | правила, инварианты, вычисления над значениями | FastAPI и SQLAlchemy |

**Сервис показателей** — единственное место, где считаются сигналы, лестница внимания,
признак жизни, скорость ответа, отклонения и прогноз. Его вызывают API, отчёты,
уведомления и сценарий «что если». Два источника расчёта разошлись бы в цифрах, и доверия
не было бы ни к одному.

**Единица работы.** Сценарий открывает одну транзакцию; внешние действия выполняются после
фиксации через исходящую очередь в базе. Журнал изменений пишется в той же транзакции.

**«Что если»** — тот же код расчёта в режиме без записи. В базу не попадает ничего, пока
не нажато «применить».

## 3. Frontend

`frontend/src`:

```
app/        маршруты, провайдеры, тема, определение устройства, PWA
shared/     клиент API из OpenAPI, набор компонентов (shadcn/ui), i18n, время, токены
sections/   по каталогу на каждый раздел ТЗ
```

- **Устройство определяет набор функций**, а не только сетку: телефон — решить, увидеть,
  записать; ноутбук — вносить и планировать; монитор — обзор и режим «Совещание».
- **Токены** — единственный источник цвета; тем две, обе проверяются на контраст счётом.
- **Данные** идут через TanStack Query: опрос раз в 15 секунд, немедленное обновление при
  возврате на вкладку, остановка при скрытой вкладке.
- **Клиент API генерируется** из OpenAPI: контракт не расходится с сервером.

## 4. Данные

- PostgreSQL 16, схема `orbita`. Схема меняется только миграцией Alembic.
- У каждой редактируемой записи есть версия: одновременная правка двумя людьми даёт
  честный ответ «запись изменил помощник», а не молчаливую перезапись.
- Журнал изменений неизменяем и защищён триггерами.
- Происхождение данных видно на данных: сырое написание ФИО хранится рядом с
  сопоставленным сотрудником, у срока записано, откуда взялся год.
- **Ветки базы**: рабочая — с реальными данными; демо — с вымышленными. Превью каждого PR
  получает копию **демо**. Реальные данные в превью не попадают никогда.

## 5. Файлы

Порт `FileStorage`. В облаке — Vercel Blob в закрытом режиме, на сервере агентства —
S3‑совместимое хранилище. Файл загружается браузером напрямую по подписанной ссылке: тело
запроса к функции ограничено 4,5 МБ, и большие презентации через API не проходят.

## 6. Задачи по расписанию

Порт `Scheduler`. Обработчик вызывается по защищённому адресу `/internal/jobs/{name}`:
в облаке — расписанием платформы, на сервере — cron. Все задачи идемпотентны и умеют
догонять пропущенный запуск. Сейчас это: утренняя сводка в 08:30 по Ташкенту, ежедневные
снимки состояния, проверка наступающих сроков, ночной сброс демо‑данных.

## 7. Доступ

Личная секретная ссылка ставит cookie сессии на 30 дней. Проверка одна, на входе в API.
Роль подписывает действие в журнале и ничего не прячет: оба пользователя видят всё.
API принимает запросы только через прокси Netlify.

## 8. Окружения и конвейер

| Окружение | Когда обновляется | Данные |
|---|---|---|
| превью PR | на каждый push в ветку | копия демо‑базы |
| рабочее | после слияния в `main`, по кнопке | реальные |

Проверки в CI обязательны: ruff, mypy, import-linter, pytest на настоящей PostgreSQL,
eslint, prettier, tsc, vitest, сборка, миграции (одна голова, схема совпадает с моделями),
e2e на превью, бюджет размера сборки.

Откат: предыдущая выкладка одним действием; миграции пишутся по схеме «расширить →
переключить → сжать», чтобы откат кода не требовал отката схемы.

## 9. Границы

Чего в системе нет и не планируется без отдельного решения: постоянного воркера и Redis,
антивируса и преобразователя документов, внешних моделей ИИ, собственного бота, входа по
паролю, разграничения доступа между пользователями, обмена с SETA (порт есть, подключения
нет).
