## 1. Что это за продукт

**ORBITA — рабочее пространство на двоих.** Заказчик — помощник заместителя директора
Агентства космических исследований и технологий «Ўзбеккосмос» (Узбекистан, Ташкент).
Пользователей ровно два:

| | Помощник | Руководитель (заместитель директора) |
|---|---|---|
| Что делает | вносит и поддерживает данные, грузит таблицы «Ижро», готовит доклады | смотрит, анализирует, **принимает решения**, меняет сроки |
| Где работает | ноутбук — основное, телефон — захват на ходу | **iPhone — основное**, ноутбук и большой монитор — разбор и совещания |

Ограничений между ними нет: оба видят всё. Роль подписывает действие в журнале, а не
прячет данные. Сотрудники агентства в систему **не входят** — они живут в справочнике как
ответственные.

Система отвечает руководителю на один вопрос: **что требует моего внимания сейчас и какое
решение я принимаю.**

**Два свойства продукта определяют всё остальное:**

1. **Презентационный слой — это и есть система.** Не понял картину за полминуты с
   телефона — задача не выполнена, сколько бы функций ни работало.
2. **Стоимость ввода определяет, выживет ли продукт.** Данные вносит один человек между
   делом. Что можно вычислить — вычисляется, а не вводится.

**Десять разделов**, у каждого один вопрос:

| Раздел | Вопрос | Блок |
|---|---|---|
| Пульт | что требует внимания сейчас по всем разделам | 1 |
| Программы | где мы по многолетним программам и что должно случиться до конца года | 1 |
| Проекты | где мы по каждому проекту и подпроекту | 1 |
| Задачи | что делать, кому и к какому сроку | 1 |
| Ижро | что на контроле, что горит, работает ли ответственный, из-за кого сорвётся | 2 |
| Взаимодействие | кто кого ждёт: организации, письма, соглашения | 2 |
| Доклады и мероприятия | готовы ли мы к дате и кто задерживает | 2 |
| Идеи и карты | что предложено и как это связано | 3 |
| Календарь | что и когда наступит, где тесно | 1 |
| Управление | справочники, загрузка, обход, ссылки доступа | 0 ✅ |

**«Ижро»** (узб. «исполнение») — реестр поручений вышестоящих органов: Администрации
Президента, Кабинета Министров, законодательных актов. Приходит контрольными таблицами
Word на узбекской кириллице. Это самая ценная часть предметной области.

## 2. Как устроена работа с заказчиком

- Работаем **крупными блоками**, не тикетами. Один блок — одна ветка — один PR.
- Цикл блока: **экран → API под утверждённый экран → тест визуала → тест кода → отчёт**.
  Порядок «экран первым» введён 20.09 по итогам аудита: прежде писали API вперёд экранов и
  получили 45 эндпоинтов, из которых интерфейс вызывал 5.
- **Объём блока не меняется посреди блока.** Новое требование записывается и обсуждается
  на приёмке.
- Приёмка: заказчик смотрит превью PR, даёт замечания **одним пакетом**, после правок
  нажимает выкладку.
- **Ключи вводит только заказчик.** Разработка их не видит. Не предлагать вводить ключи.
- Заказчик пишет быстро и с опечатками — читать по смыслу, не переспрашивать по мелочам.
- Заказчик просил **не запускать десять агентов и десять окружений**. Работать самому.

### Что заказчик решил (и это не пересматривается без нового ADR)

| Решение | Где записано |
|---|---|
| Облако сейчас (Netlify + Vercel + Neon), переезд на сервер агентства позже | ADR-0028 |
| Вход **по личной ссылке**, без паролей и экранов входа | ADR-0029 |
| Стек интерфейса: React 19, Tailwind 4, shadcn/ui, Motion, Recharts | ADR-0030 |
| Обновление **опросом**, а не постоянным соединением | ADR-0034 |
| Расписание — в GitHub Actions, не на площадке | ADR-0035 |
| Темы: светлая основная + приглушённая сланцево-синяя («не очень тёмная») | ADR-0030 |
| Реальные данные агентства живут в облаке — риск назван, решение его | ADR-0028 |
| Бот SETA работает отдельно; фундамент синхронизации заложить, но не подключать | план, блок 3 |
| Репозиторий **публичный**; ключей в нём нет | инвариант 12 |

### Чего не делать (снято решением заказчика)

Redis, постоянный воркер, ClamAV, Gotenberg, MinIO, вход по паролю, гриф и выдача наружу,
разграничение доступа между пользователями, встречи, Google-календарь, внешние модели ИИ,
собственный Telegram-бот, учёт трудозатрат в часах, ЭЦП и документооборот, публичный
портал, конструктор отчётов.

## 5. Правила, которые нельзя нарушать

### Язык

- Документация, коммиты, комментарии, сообщения пользователю — **по-русски**.
- Идентификаторы, таблицы, поля, пути API — **по-английски**. Смешивать внутри одного
  идентификатора нельзя.
- **Ни одной строки текста в коде интерфейса** — только ключи перевода.
- Содержание поручений «Ижро» хранится как есть, на узбекской кириллице, **не переводится**.
- Имена работ, шагов и входов в GitHub Actions — **латиницей**. Кириллица в имени входа
  `workflow_dispatch` делает файл невалидным целиком (уже обжигались).

### Инварианты (полный список — CLAUDE.md)

1. **«Просрочено» вычисляется, не хранится.** Как и все ступени лестницы внимания.
2. **Одни цифры везде.** Все показатели считает `services/metrics.py`. «Что если» считает
   тем же кодом и **не пишет в базу ничего**.
3. **Аналитика только от вопроса.** У показателя есть вопрос руководителя, ответ числом,
   дата данных и действие. Нет действия — нет показателя.
4. **У поля один хозяин.** Привоз «Ижро» меняет только поля источника, никогда наши.
5. **Каждое изменение — в журнал**, сервисным слоем, в одной транзакции.
6. **Происхождение данных видно на данных.** Сырое написание ФИО хранится всегда.
7. **Свежесть показывается всегда:** «по таблице от 15.09».
8. **Время:** timestamptz, хранение UTC, показ Asia/Tashkent, просрочка по календарным дням.
9. **Схема — только миграцией Alembic.** `create_all` в рантайме запрещён.
10. **Фоновые задачи идемпотентны.**
11. **Реальные данные — только в рабочем контуре.** Превью от ветки `demo`.
12. **Ключей в репозитории нет** — он публичный.
13. **Доступ по личной ссылке**, проверка в одном месте.
14. **Никаких полей «на будущее»** — только под конкретный критерий приёмки.
15. **У редактируемой записи есть версия** (защита от молчаливой перезаписи).

### Стандарты кода (введены 20.09)

- Комментарий объясняет **почему**, а не что. Решение, оплаченное замером или счётом по
  настоящим данным, записывается рядом вместе с этим наблюдением.
- **Причина, которая есть в ADR, заменяется ссылкой на ADR.** Пересказ ADR в коде создаёт
  второй источник правды — именно так `orbita.ts` начал обещать несуществующую команду.
- Комментарий не обещает того, чего нет.
- Цвет — только токеном, проверяется stylelint.

## 6. Как запустить

```bash
make doctor        # ПЕРВОЕ: контейнер, порты, .env, секреты, головы миграций, BOM
make up            # postgres в docker, порт 55433
make migrate       # alembic upgrade head
make seed          # справочники
make dev           # backend :8000, frontend :5173
make test          # pytest + vitest
make e2e           # playwright (нужны поднятые backend и frontend)
make check         # ruff + mypy + import-linter + eslint + stylelint + tsc + документы
make job n=deadline-check
```

На Windows — `./make.ps1 <цель>` (тот же список).

### Особенности Windows, на которых уже теряли время

| Грабли | Лечение |
|---|---|
| `npm` разрешается в `npm.ps1`, который ломается на кавычках в аргументах | вызывать `npm.cmd`; в `make.ps1` уже так |
| `make.ps1` без BOM читается PowerShell 5.1 как ANSI и падает | BOM обязателен; `make doctor` проверяет |
| Bash-инструмент **съедает обратные слэши** в heredoc | писать патч-скрипт файлом (Write) и запускать его, либо `chr(92)` |
| На 55432 стоит PostgreSQL **соседнего проекта SETA** | ORBITA на 55433; `make doctor` проверяет, чей это порт |
| PowerShell: `2>&1` на native exe даёт ложный «сбой» | не перенаправлять stderr — он и так захвачен |
| В выводе Bash-инструмента кириллица бывает «кракозябрами» | это артефакт канала, файлы целы; проверять через PowerShell |

### Окружение (`.env`, 18 ключей)

Обязательные: `ORBITA_SESSION_SECRET` (≥32 символов), `ORBITA_JOBS_SECRET` (≥16, **только
латиница** — едет в заголовке HTTP), `ORBITA_DATABASE_URL` либо части `ORBITA_DB_*`,
`ORBITA_BASE_URL` (из него собираются личные ссылки — при неверном значении ссылка ведёт
в никуда).

### Первый вход в систему

```bash
cd backend && uv run python -m app.access_cli assistant
```

Печатает ссылку один раз. Открыть её в браузере — поставится cookie `__Host-orbita` на 30
дней. Дальше перевыпуск — в разделе «Управление».

## 10. Главные находки аудита (чтобы не наступить снова)

Полностью — `docs/audit/AUDIT-2026-09-20.md`. Коротко:

- **Диагноз:** ORBITA v3 была фундаментом под ТЗ v1.0, переименованным в фундамент под
  ТЗ v2.0. 45 эндпоинтов при 5 используемых, 26 таблиц при 8 ненужных, 362 теста при ~208
  по снятому объёму. Именно это сейчас и исправляется.
- **Документы обещали шесть вещей, которых в коде нет:** сервис показателей, единица
  работы с исходящей очередью, генерация клиента из OpenAPI, поле версии, порт
  `FileStorage`, shadcn/ui. Три из шести закрываются текущей работой.
- **Опрос раз в 15 секунд задан по умолчанию для всех запросов** (`main.tsx:28`) — это
  ≈276 тыс. вызовов функции в месяц для двух человек и база, которая не засыпает весь
  рабочий день. ADR-0034 предписывал «дешёвый запрос с меткой изменений» — не сделано.
  Исправление даёт 276 тыс. → 65 тыс. без разницы для пользователя.
- **Холодный старт ни разу не измерен** при нормативе ТЗ «первый экран меньше 2,5 с».
  Замерить до первой выкладки.
