# Волна A — Основание «Ижро»

Модель, домен и API реестра поручений. Блокирует волны B, C, D и S.

Всё в этой волне опирается на разбор настоящих данных заказчика — 165 строк трёх
контрольных таблиц. Числа в критериях приёмки взяты оттуда и проверяемы:
[PLAN, раздел «Что установлено по данным»](../PLAN.md).

## ORB-101. Схема «Ижро»: пять таблиц, миграция `0018` — **закрыт 18.09.2026**

**Вес:** M · **Зависит от:** ORB-100 · **Блокирует:** ORB-103

> Номер миграции сместился с `0017` на `0018`: `0017` занята снятием входа
> ([ADR-0026](../adr/ADR-0026-no-login-perimeter-auth.md)), которое пришло между
> нарезкой карточки и работой по ней.

**Что сделать.** Пять таблиц по [ADR-0025](../adr/ADR-0025-ijro-standalone-register.md):
`ijro_documents`, `ijro_assignments`, `ijro_person_aliases`, `ijro_org_aliases`,
`ijro_imports`. Модели наследуют `Auditable` (`backend/app/repos/models/audit.py:21`) и
регистрируются в `backend/app/repos/models/__init__.py` — забытый импорт даёт миграцию,
молча удаляющую таблицу.

Расширить `CHECK entity_type_is_known` у `comments` и `documents`: поручение становится
владельцем ленты и вложений, новых таблиц под них не заводится.

**Критерии приёмки.**

- [x] `make migrate` применяет, `alembic downgrade -1` откатывает, `make heads` показывает
      одну голову. Проверено прогоном вперёд, назад и снова вперёд.
- [x] `UNIQUE (document_id, band, due_on)` существует и работает: вставка дубля даёт
      нарушение ограничения на стороне базы, а не на стороне кода.
- [x] `band` допускает `NULL` — одна строка из 165 законно без пункта.
- [x] `CHECK`: `is_co_executor = true` без `lead_organization_id` не вставляется.
- [x] `ijro_documents.code_norm` уникален.
- [x] `due_precision` заведён со значениями `exact` и `end_of_year`, по умолчанию `exact`.
- [x] Реплика и вложение цепляются к поручению: `entity_type = 'ijro_assignment'`
      проходит `CHECK` у обеих таблиц.
- [x] `backend/tests/test_conventions.py` и `test_migrations.py` зелёные: соглашения об
      именовании соблюдены, наивных дат нет.

**Чего не делать.** Не заводить связь с `projects` и `tasks` — её нет по решению
заказчика. Не добавлять полей «на будущее».

**Итог.** 13 тестов схемы, все ограничения проверены на стороне базы. Всего в наборе 450
тестов бэкенда. Словари значений для `CHECK` собираются из перечислений, а не переписаны
руками: переписанный список расходится с кодом молча.

## ORB-102. Домен «Ижро»: нормализация, банд, год, состояния — **закрыт 18.09.2026**

**Вес:** M · **Зависит от:** ORB-100 · **Блокирует:** ORB-103, ORB-104

**Что сделать.** `backend/app/domain/ijro.py` — **без SQLAlchemy и FastAPI**, это требует
контракт import-linter. Чистые функции:

- нормализация номера документа: «Фармон ПФ-155-сон 14.10.2024 й» и «Фармон ПФ-155
  14.10.2024» дают один `code_norm`; запасной путь для 12 ячеек без узнаваемого префикса —
  сырая строка, приведённая к канону;
- нормализация ФИО: схлопывание пробелов, `И.Фамилия` → `И. Фамилия`, замена латинских
  омоглифов на кириллические (`X→Х, K→К, O→О, P→Р, A→А, B→В, C→С, E→Е, H→Н, M→М, T→Т, Y→У`);
- извлечение банда тремя формами по убыванию точности и `band_sort` разбором на числовые и
  буквенные части;
- восстановление года: месяц из ячейки, год из заголовка таблицы, признак перенесённой
  просрочки, `due_year_source`;
- разрез ответственного по маркеру «Асосий ижрочи» — по вхождению, а не по абзацу;
- переходы `state` и вычисление просрочки.

**Итог проверки на настоящих данных** (прогон руками, не в CI — файлов агентства в
репозитории нет):

| Что | Значение |
|---|---|
| Строк разобрано | 165 |
| Пункт извлечён | **164** — непопавшая строка та самая, что законно без пункта |
| Срок восстановлен | **165 из 165** |
| Перенесённых просрочек найдено | **5** — совпало с независимым подсчётом |
| Документов после склейки | **59** из 66 написаний, похожих-но-неслитых не осталось |
| Людей после склейки | **19** из 29 написаний |
| **Групп по ключу (документ, банд, срок)** | **164 из 165 строк**, единственный повтор — строка, приведённая в источнике дважды байт в байт |

49 тестов домена идут без базы. Три правила пришлось уточнить по данным, а не по замыслу:
«банд» закрывает обозначение (иначе в пункт утекал год из содержания), голое число после
слова — уже содержание, и точка перед дефисом необязательна («7.б.-банд»).

**Критерии приёмки.**

- [x] На зафиксированных образцах банд извлекается из **164 строк из 165**; строка без
      банда — законное состояние, а не ошибка.
- [x] `X. Рахмонов` и `Х. Рахмонов` дают одно нормализованное написание; `Қ. Эрматов` и
      `K. Эрматов` — тоже.
- [x] **`Ш. Арибжанов` НЕ сводится с `А. Арибжанов`** — отдельный тест с явным
      комментарием, зачем он: алгоритм, который их склеит, испортит показатель загрузки
      молча.
- [x] `Арибжанов` и `Арибжонов` автоматически **не** склеиваются: это решает человек.
- [x] `band_sort` ставит `2.9` перед `2.10`.
- [x] Месяц срока раньше месяца блока → строка помечена как перенесённая просрочка, год
      не сдвинут, `due_year_source` заполнен.
- [x] Срок 25 декабря года таблицы получает `due_precision = end_of_year`; **правило
      читается из `settings`, а не зашито константой** — тест меняет настройку и проверяет,
      что точность назначается по новой дате.
- [x] Поручение с `end_of_year` не считается «горящим» за три дня до своей даты.
- [ ] «Просрочено» нигде не хранится как значение `state` — только вычисляется.
- [x] `mypy --strict` по `app/domain` и `lint-imports` зелёные; тесты идут **без базы**.

## ORB-103. Сервис и API поручений

**Вес:** L · **Зависит от:** ORB-101, ORB-102 · **Блокирует:** ORB-105, ORB-108, ORB-118

**Что сделать.** Сервис и роутеры `/api/v1/ijro/...`: список поручений с фильтрами в
адресе, карточка поручения, **карточка документа** со всеми его поручениями, смена
состояния, поля `problem` и `proposal`. Лента хода исполнения — через существующий
`services/comments.py`, вложения — через `services/documents.py`. Номер вида `IJR-2026-001`
через `services/codes.py`. Роутер заводится через `transactional_router`
(`backend/app/api/transaction.py`).

**Критерии приёмки.**

- [ ] Поручение заводится, правится, получает состояние; список фильтруется по источнику,
      ответственному, состоянию, сроку и признаку соисполнителя.
- [ ] Карточка документа отдаёт все его поручения одним запросом — **не N запросов на
      карточку**.
- [ ] Смена состояния попала в `audit_log` **без единого явного вызова записи в журнал**:
      работает примесь `Auditable`.
- [ ] Реплика пишется и читается через `GET /timeline`; текст реплики в журнал не попал
      (`audit_hides_values`).
- [ ] Вложение цепляется, версия считается по sha256, ссылка выдаётся.
- [ ] Просрочка приходит вычисленной в ответе, в базе её нет.
- [ ] Ответ «создано» уходит **после** фиксации транзакции.
- [ ] Ошибки в формате RFC 9457; 401 отделён от 403.

**Чего не делать.** Не писать здесь ввоз — это ORB-105. Не делать экранов — ORB-108.
